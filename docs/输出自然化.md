# 胡桃输出自然化优化记录

> 目标：让胡桃在微信里的输出**越像真人越好**——包括句子长度、分段、emoji、节奏、互动方式；
> 同时把"底层逻辑"（人设锚定、风格约束、反 AI 形态）落到文件与代码里，而不是只靠提示词碰运气。
> 状态：**已实施并评测通过**（2026-09-13）

---

## 一、诊断出的 6 个根因

| # | 问题 | 影响 |
|---|---|---|
| 1 | `SOUL.md`/`IDENTITY.md` 残留 **14+4 处 `[citation:N]` 标记** | 污染系统提示、浪费 token、可能被模型模仿进输出 |
| 2 | **人称混乱**（第一人称与"你鬼点子极多"混用） | 削弱"我是谁"的锚定，易出现你我混用 |

| 5 | **缺少"分享见闻"的黄金样例**（现有样例只有自我介绍） | few-shot 缺失 → 风格不稳 |
| 6 | **USER.md 是空模板** | 她不知道"旅行者"是谁，聊天缺"熟人感" |

## 二、已实施的优化

### 1. 重写人设文件（`persona/`，部署至 `~/.openclaw/workspace/`）

| 文件 | 变更 |
|---|---|

| `IDENTITY.md` | 清洗 citation、修正人称、去重；保留"我不是什么/我是什么"边界 |
| `USER.md` | 由空模板填充为**真实档案**：称呼「旅行者」、时区 UTC+8、日常在折腾终端/代码、讨厌 AI 腔、在意"像不像活人"、期望"别老回头问" |

### 2. 精简每条消息的注入（`scene/delivery.py`）

`OUTPUT_FORM` 由 **622 字 → 161 字**（风格已由 SOUL.md 承载，此处只留"本次怎么发"的要点与 `|||` 约定）。

### 3. 代码级"反 AI 形态"兜底（关键）

**问题**：叙事类内容天然被模型拆成"起-承-转"三段 → 出现「3 条、每条 30~60 字」这种最像 AI 的形态（实测复现）。

**解法**：在 `_split_bubbles()` 中加确定性规则——
> 若拆分结果是**≥3 条、且每条都在 20~80 字、且长度彼此相差 ≤6 字**（"多条中等长度且整齐"），
> 就把中间几条并成一条，制造「短—长—短」的自然落差；

这样即使模型不遵守人设里的禁忌，**也发不出这种形态**（代码保证，非提示词祈祷）。
注意**只在中等长度时才合并**：连发几条短句（`hhhh` / `绝了` / `你说呢`）本来就是真人常态，
合并反而不像。

| 输入 | 处理 |
|---|---|
| 24+47+58 字三条 | ✅ 并成 2 条（24 + 105） |
| 9+12+18 字三条 | ✅ 保持 3 条短句（短促连发是真人常态） |
| 6 + 48 字两条 | ✅ 保持 2 条 |

### 4. 节奏与打断机制

- **分次讲述**：一件事按 `|||` 拆成 2~4 条（上限 5 条），**长短交错**——
  短开场 → 长细节 → 短反应收尾；每条是一个完整意思，合起来把事讲完
- **打字间隔（每条都不一样）**：`间隔 ≈ 思考时间(0.4~2.0s) + 本条字数 ÷ 11字/秒 + 随机分心`
  - 短促反应（≤8 字）几乎立刻跟上（×0.35~0.7）
  - 约 12% 概率插一次 2.5~6s 的长停顿（走神/去倒水）
  - 上限 8s。实测一条 3 段的故事总耗时 7~13s（原先均匀 0.6~3.0s，读起来像机器在定量推送）
- **打断处理**：发现旅行者已在回话 → 立即停止后续气泡
- **推送周期可变**（20~90 分钟随机）+ 事件降频（×0.45）

> **内容不变量**：`"".join(bubbles)` 与原文（去掉 `|||` 与首尾空白）**逐字相同**。
> 拆分只改形式，一个字都不改——由 `test_output_form.py` 覆盖（210 条语料含随机拼接）。

### 5.1 分隔符从 `|||` 改成空行（修掉直聊漏出）

**问题**：`|||` 这个约定只在**引擎驱动的主动发言**那条路上被切开；
用户**直接跟胡桃聊天**时走 OpenClaw 自己的投递，没人切，标记就**原样发到微信**里了。
实测在她直聊会话里翻到两条带 `|||` 的回复。

**为什么不能靠出站过滤**：OpenClaw 的 `hooks` 是入口 webhook，没有出站消息改写钩子，
要做得写插件，成本远高于收益。

**修法**：换分隔符。`_split_bubbles()` 本来就同时支持**空行**与 `|||` 分段，改成主用空行：

| 分隔符 | 引擎路径 | 直聊路径 |
|---|---|---|
| `\|\|\|` | ✅ 分条发送 | ❌ 原样漏给用户 |
| **空行** | ✅ 分条发送（同一个切分器） | ✅ 就是个段落换行，**完全自然** |

空行即使漏出去也没有痕迹——微信本来就有段落。同时在 SOUL.md 里明写
「别写 `|||` 这类符号，微信里会原样显示出来」，把原因讲清楚，模型更容易守。
`|||` 的切分能力保留作兼容，不再教给模型。

实测（本地 9B）：两次输出都不含 `|||`、改用空行；引擎切成 4 条 [39/48/61/45]，内容不丢。

### 5. 括号动作神态（早期禁用，后按要求加回）

早期自然化把「`（笑）`」这类括号动作当 AI 腔一并禁掉了。**现已恢复并写进规范**——
带身体动作的聊天更像真人在打字，尤其配合她的性格（叉腰、扶帽、眯眼笑）。

**规范**（`SOUL.md` 的【动作神态】节）：全角括号、每条最多 1 处、2~8 字、
写具体身体动作而非抽象心理（`（叉腰）` ✅ / `（心里有点难过）` ❌）、两三句带一次别满屏。

**代码侧配套**：气泡切分改成**括号感知**（这是必须一起改的，否则 `（笑眯眯地，把茶推过去）`
会被从中间切开、变成半截「（」加半截「）」）：

- `_depths()` 算每个位置的括号深度
- `_split_sentences()` 只在**括号外**的句末标点断句（括号里的句号不算句末）
- `_safe_cut()` 挑切点时优先括号外标点，找不到就退到 ≤max_len 的最后一个括号外位置

| 输入（切分阈值 45 字） | 处理 |
|---|---|
| 30 字 +`（`+40 字+`）`+30 字 | ✅ 切在 30（括号前），而不是 45（括号内） |
| 40 字 +`（笑眯眯地，把茶推过去）`+20 字 | ✅ 切在 40，不切在括号内那个逗号后 |
| 括号里带句号 `（他叹了口气。然后又笑了）` | ✅ 不在括号内断句 |

由 `test_output_form.py` 的「括号动作不会被切两半」6 项断言覆盖（含括号配平检查）。

## 五、多模态输出

真人聊天不只发文字。胡桃可**按需配图**（默认每次最多 1 个媒体，约每五六条用一次）：

| 标记（写在回复里） | 引擎行为 |
|---|---|
| `[[img_gen: 画面描述]]` | 调通义万相生成 → 发送图片（带描述作配文） |
| `[[img: /完整/路径.png]]` | 发送已有图片 |
| `[[img: 角色 关键词]]` | 从本地官方图库取图（见 5.2），`胡桃立绘` 这种 100% 保真 |
| ~~`[[voice: 要说的话]]`~~ | **已禁用**（见下） |

**实现**：`scene/delivery.py` 的 `_parse_media_markers()` 解析标记并剥离（用户看不到标记），
`_deliver_media()` 依次生成/取图并发送；文本部分照常走多气泡节奏。

**实测**（海灯节试灯事件）：她自主选择配图 → 生成成功 → 图片+配文送达微信 ✅

> 工具：`tools/gen_image.py`（通义万相异步 API，走 curl 规避 python.org 版 CA 缺失问题）

### 5.0 语音输出已禁用（微信不支持音频）

Thunder-TTS 的胡桃音色链路本身是通的（`hutao_tts.sh` 合成 wav → 投递成功），
但**微信渠道收不了音频文件，发出去就是错误**，所以整条语音输出关掉：

- 引擎侧：`config.sessions.json` 的 `voice_enabled: false`（默认关，渠道支持音频时才开）
- 人设侧：`persona/SOUL.md` 删掉了发语音的写法，改成明文禁止
  （"永远不要写 `[[voice: ...]]`，也别提'给你发个语音'"）
- **工作区模板侧**：`~/.openclaw/workspace/AGENTS.md` 原本有一条默认模板指令
  *"Voice storytelling: if you have `sag`, use voice for stories…"*——**这条在鼓励她发语音**，
  已改成"本渠道收不了音频，一律用文字"，`MEMORY.md` 里的 TTS 条目也标了停用
- 兜底：万一她还是写了 `[[voice: 内容]]`，`_parse_media_markers()` 会**把这段文字转成普通文字气泡**
  发出去（内容一个字不丢），只打印一条提示，绝不产出音频文件

### 5.1 专有名词锚定（关键，否则图不对人）

生图模型**不认识 IP 名词**。早期直接把「胡桃站在璃月港码头」丢给通义万相，出来的是
「红头发少女站在某个赤墙黄瓦的外国海港」——人不对、地方也不对。

**解决**：`tools/image_anchors.json` + `tools/gen_image.py` 的 `enrich_prompt()`。
生成前用子串匹配扫描 prompt，命中「胡桃」「璃月港」等词就把对应的**精确视觉特征描述**追加进去：

```
输入：胡桃站在璃月港码头看海
命中：角色:胡桃, 场景:璃月港
实际下发：胡桃站在璃月港码头看海，红褐色渐变色双马尾少女，梅花形状瞳孔，头戴黑色乾坤泰卦帽…
         ，《原神》璃月港：飞檐翘角的中式楼阁与青瓦屋顶…，《原神》游戏美术风格…
```

- 词典覆盖：19 个角色（璃月全员 + 温迪/甘雨等）、13 个场景（璃月港/往生堂/玉京台/群玉阁/万民堂/绝云间…）、
  3 类元素（霄灯/神之眼/送葬队伍）；多角色多场景可叠加（「刻晴和凝光在玉京台」三个锚点全中）
- `max_prompt_chars: 480` 截断保护；`--raw` 参数可关闭锚定（调试用）
- 命中情况打印为 `PROMPT_ENRICHED 角色:胡桃,场景:璃月港`，日志可见

**效果验证**（用胡桃自己的视觉能力做 A/B 判图，`openclaw agent` + `image` 工具）：

| | 原图（raw） | 锚定后（enriched） |
|---|---|---|
| 飞檐翘角楼阁 | ❌ 无 | ✅ 多层木质楼阁、灯火通明 |
| 红灯笼 | ❌ 无 | ✅ 成串悬挂 + 孔明灯 |
| 船只风格 | 西式多桅帆船 | ✅ 中式商船 |
| 码头氛围 | 泛用海港黄昏 | ✅ 东方港口夜市 |

> 结论：**背景锚定是碾压级提升**（「外国港口」→「璃月港」）。
> 人物部分提升有限——t2i 模型对「刺绣纹样/梅花瞳孔」这类小尺度细节还原力天然不足，
> 强识别特征（双马尾+黑帽子）在锚定后能稳定出现，更细的纹样不要指望。
>
> 配套：`persona/SOUL.md` 已写死规矩——**画面描述必须用专有名词，不许用代词**，
> 否则「我在海边」这类描述根本没有锚点可匹配。

### 5.2 官方图库复用（补住生图的短板）

5.1 解决了背景（璃月港像了），但**人物一致性解决不了**——生图模型对「胡桃」没有先验，
再长的描述也只能出「像胡桃的路人」。所以补一条 0 成本的路：**直接发官方图**。

| 场合 | 走哪条路 | 标记 |
|---|---|---|
| 画面主体是她本人（打招呼 / 情绪 / 节日） | 官方图库 | `[[img: 胡桃 立绘]]` |
| 分享见闻、需要具体场景 | 生图 | `[[img_gen: 胡桃在璃月港码头]]` |
| 指定文件 | 直发 | `[[img: /完整/路径.png]]` |

**实现**（`tools/gallery.py` + `gallery/`）：

- 图源：**Enka.Network**（`tools/fetch_enka.py`）——镜像的是游戏内原始素材，
  地址可由角色 ID 直接拼出、**不限流**，一条命令抓完全阵容（抽卡立绘/半身/头像/名片）；
  Enka 缺白术、闲云，自动改走 `genshin.jmp.blue` 并用 `sips` 把 webp 转 png
- 补充源：**原神观测枢 wiki**（`tools/fetch_gallery.py`）——Enka 只有游戏内素材，
  官方**生贺图**只能从 wiki 拿（缩略图链接去掉 `/thumb` 与尺寸后缀即全尺寸原图，
  `alt` 属性就是中文图名 → **文件名直接当关键词**，实测拿到 2250×2250 的立绘与 2500×2500 的生贺图）
- **wiki 是 IP 级封禁**：阿里云 WAF 返回标题为「请求已被拦截」的页面，**不是 JS 挑战**，
  浏览器手动操作同样救不了；实测约 3 页/次、冷却 5~10 分钟。所以主图源必须是 Enka
- 检索评分：目录名命中 5 分 > 文件名词 4 分 > 宽松子串 2 分；
  **第一个词是主题词，必须命中**（写「钟离 立绘」而图库没有钟离时返回 MISS，
  而不是拿「立绘」去匹配、发回一张胡桃图）
- 同分时按类别裁决（立绘 > 节日 > 剧情 > 表情 > 动作），所以只写「胡桃」得到立绘，
  不会随机甩一张 7MB 的动作 GIF；候选池内 LRU 轮换，候选 ≥2 张就不会连着发同一张
- 文件名剥掉角色名前缀后也当关键词：`甘雨/立绘/甘雨半身.png` 能命中「半身」
  （中文连写没有分隔符，拆词拆不出来，靠这条补）
- `gallery/tags.json` 可给图片补别名（`打招呼`/`开心`/`生日` 等），文件名里没有的词也能命中

**规模**：18 个角色、120 张、165MB（璃月全员 + 温迪/甘雨/魈等）。

**发布形态**：官方素材版权归米哈游，图片已被 `.gitignore` 排除，
仓库只保留 `gallery/README.md` 与 `tags.json`（含图源地址与抓取命令），各人本地自行拉图。
