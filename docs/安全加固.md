## 四、工具权限：**已放开胡桃**（2026-09-13 用户决策）

用户要求恢复胡桃的完整管理能力，已移除 messaging 限制。**验证：实际授予 23 个工具**
（`exec`/`process`/`read`/`write`/`edit`/`apply_patch`/`web_search`/`web_fetch`/`sessions_spawn`/`subagents`/`image`/`memory_search` 等）。

备份：`~/.openclaw/openclaw.json.bak.pre-unlock`

### 放开后的残余风险（已评估，用户接受）

| 风险面 | 说明 | 可选的进一步护栏 |
|---|---|---|
| **① 发送者面（最直接）** | 微信渠道**未配发送者白名单**——谁能给 bot 发消息，谁就能命令 agent | 给 `channels.openclaw-weixin` 配 allowlist / `accessGroups`，仅允许本人 wxid |
| **② 间接注入（最隐蔽）** | agent 读取外部内容（`web_fetch`/抓取网页/用户转发的链接/图片文字）时可能被注入指令 | 无彻底解法；可对来源做白名单，或对危险工具加审批 |
| ③ 供应链 | 插件/MCP 投毒 | 已加 `plugins.allow` 白名单 |
| ④ 本地进程 | 调 gateway/hooks | 回环 + token（低） |
| ⑤ 微信上游 | bot 云连接被劫持 | 概率极低 |

### 采用方案：**监测告警（不拦截）**

用户判断正确并有数据支撑——微信 bot 是**独立账号**（`YOUR_BOT_ACCOUNT@im.bot`），绑定在用户本人 openid 上，
历史交互**仅 1 个发送者、1 个会话**，即现实中只有本人能与胡桃对话。因此**不设硬护栏**，改为：

- `scene/security.py`：读取微信 context-tokens 的发送者列表，与配置中的本人 id 比对
- `main.py`：每 20 轮（约 10 分钟）检查一次，发现**未知发送者**即写入运行日志（WebUI 可见）并打印告警
- 配置：`"security": { "weixin_owner_ids": ["YOUR_WECHAT_OPENID@im.wechat"] }`

> 任何新发送者都会在 context-tokens 与会话存储中留下痕迹，故该监测可靠；且**零侵入**——不影响胡桃的完整能力。

**（备选，未启用）硬护栏配置**：

```jsonc
// A. 按发送者限权（防"别人给 bot 发消息就能用 shell"）
{ "tools": { "toolsBySender": {
    "channel:openclaw-weixin:YOUR_WECHAT_OPENID@im.wechat": {},   // 本人：无限制
    "*": { "deny": ["group:runtime", "group:fs"] }                          // 其他发送者：无 shell/文件
} } }

// B. 微信渠道发送者白名单（更根本：直接限制谁能触达）
{ "channels": { "openclaw-weixin": { "allowFrom": ["YOUR_WECHAT_OPENID@im.wechat"] } } }
```

> 注意：`toolsBySender` 按**特异性单条匹配**（源码 `resolveToolsBySender` 返回单个 entry），
> 因此本人 key 需显式给出（即使是空 `{}`），否则会落到 `*` 通配策略。

## 附：工具权限收紧方案（历史记录，当前已撤销）

**已应用（推荐方案 1）**：main agent 工具档收紧为 `messaging`

```jsonc
{ "agents": { "list": [ { "id": "main",
    "tools": { "profile": "messaging", "elevated": { "enabled": false } } } ] } }
```

| `web_search`、`web_fetch`、`browser`、`cron` | ❌ 已移除 |
| `message`、`sessions_*`、`session_status` | ✅ 保留（胡桃发消息能力不受影响） |

**验证**：收紧后实测胡桃仍正常生成并连发 2 条微信消息 ✅（`分 2 条连发（成功 2）`）

> 备份：`~/.openclaw/openclaw.json.bak.pre-tools-restrict`

> ⚠️ **副作用**：`messaging` 档不含文件工具，因此**心跳路线（路子一）不再可用**（它需要读写 `pending.json` / `replies.jsonl`）。
> 当前生产用路子二（`config.sessions.json`），不受影响。若将来要用心跳路线，需给 main 加回 `group:fs`：

### 全局 `tools.elevated`：**已评估，决定保持开启**（2026-09-13）

用户明确选择保留全局默认（日常需要 OpenClaw 执行本机命令）。风险已评估并接受：
- main agent（微信可触达）已是 messaging 档，无 exec 工具 → **提权对它无效**
- 该默认仅作用于继承 `coding` 的其他 agent（如 `venti`，无外部渠道绑定）
- 若日后判断需要收紧，改一行即可：`{"tools": {"elevated": {"enabled": false}}}`

### 参考：进一步收紧的配置形态

审计的 attack surface 仍显示 `tools.elevated: enabled` —— 这是**全局默认**（控制沙箱外提权 exec，`/elevated`）。
main 已是 messaging 档、无 exec 工具，提权对它无效；但它仍作用于继承全局 `coding` 的其它 agent（如 `venti`，目前无外部渠道绑定）。

如需彻底关闭（本项目不需要）：
```jsonc
{ "tools": { "elevated": { "enabled": false } } }
```
> 注意：若你日常用 OpenClaw 执行本机命令/运维，关闭后命令将走沙箱或需要审批。

## 五、运维建议

1. **定期审计**：`openclaw security audit`（每周或配置变更后）；深度检查用 `--deep`
2. **密钥轮换**：`hooks.token` 与网关 token 属 API 级密钥；怀疑泄露时立即轮换并同步更新 `config.webhook.json`
3. **绝不公网暴露**：网关、WebUI、Live2D 桥接三者均只应回环访问；需要远程时用 Tailscale + 网关鉴权，不要直接端口映射
4. **本地服务无鉴权但仅回环**：`log_server.py`（8620）与 `live2d/bridge.py`（8630）无鉴权，仅绑定 127.0.0.1；
   若将来要跨机访问，必须先加 token 校验
5. **本机多用户环境**：本项目运行目录建议保持 `700`/`600` 权限（已设置 `logs/`）
6. **供应商供应链**：插件安装/更新走官方 CLI，避免手动替换 `node_modules`
