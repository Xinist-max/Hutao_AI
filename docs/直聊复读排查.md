# 直聊复读排查（2026-09-27 夜）

> 症状：她直聊时"每段只改一两个字，其他一字不改，上下文完全不衔接，就跟套模板一样"。
> 硬约束：敏感内容不出本机、不切回云端模型。

## 一、先纠正一个**我自己的错误归因**

排查中途我告诉她"直聊跑在本地 35B Q2_K 模型上，量化导致复读"，她据此要求"不切云端"。
**这个归因是错的，数据不支持。** 按"有真人对话"的会话做公平对照：

| 时期 | 相邻回复对数 | ≥70% 高度相似 |
|---|---|---|
| **云端**模型时期（moonshot/kimi-k2.6） | 130 | **24%** |
| **本地**模型时期（ollama/local Q2_K） | 47 | **15%** |

**本地模型反而更低。** 而且云端时期有个会话（`a120adb3`）中位相似度 **100%**、24/29 对复读。

教训：一开始我按"会话整体在切换之后"就归因于模型，没有做**同期对照**。
对照一出来结论就反了。**先做对照，再下结论。**

## 二、复读是**真实存在**的

在当前的直聊会话里逐对核对"回复相似度"与"提问相似度"：

| 时间 | 回复相似 | **提问相似** | 判定 |
|---|---|---|---|
| 16:58:36 | 100% | 38% | 提问不同、回复完全相同 |
| 17:22:59 | 99% | 10% | 同上 |
| 17:25:29 | 87% | 10% | 同上 |
| 17:27:43 | 81% | 17% | 同上 |
| 17:46:00 | 98% | 7% | 同上 |
| 18:02:40 | 100% | 15% | 同上 |
| 18:05:05 | 85% | 19% | 同上 |

7 组的**提问相似度只有 7~38%**（问题明显不同），回复却 81~100% 相似 —— 不能用"问得像"解释。

**签名**：这些对的**回复长度也几乎一样**（143/143、290/291、330/331、**336/336/337**）。
其中一条 **336 字的回复隔了 1000 秒（16.7 分钟）逐字再现**。
随机生成极难出现这种形态，更像**上下文里的原文被整段吐回来**。

## 三、我**没能复现**它

受控实验全部无法复现，所以真因**尚未确定**：

| 实验 | 结果 |
|---|---|
| 本地模型 + 简短 system | 3 个不同问题 → 相似度 8~10%，**不复读** |
| 本地模型 + **完整 20K 系统提示词** | 相似度 11~19%，**不复读** |
| `TEMPLATE {{ .Prompt }}` 是否拍平轮次 | **不是**问题：system 指令生效（回复正好 4 字）、轮次结构被识别（答对了 2+2） |
| 复读陷阱：前 8 轮全部用同一句话回复，再问新问题 | `local` **挣脱**（相似 18%、最长公共片段 3%）；`local-v2` 也挣脱（15%/2%） |

**排除的假设**：Q2_K 量化本身、Modelfile 模板拍平、系统提示词过长。

**未排除**：真实会话里累积的**她自己的 48 条回复**（受控实验最多 8 轮、且是短模板）。

## 四、能作用于直聊的杠杆只有一个

**直聊的回复由 OpenClaw 直接生成并发出，引擎完全绕过** ——
引擎既拦不到、也无法不发。唯一能作用于那条链路的是**上下文本身**。

所以做了「说话方式守卫」（`main.py: apply_style_guard`）：

```
每 20 轮检查一次直聊会话 → 最近 3 对回复里有 2 对相似度 ≥85% → 压缩会话
```

判据用"3 对里 2 对"而不是"最近 2 对都超标"：实测真实复读窗口是
`98% / 100% / 84%` 这种形态，卡在最后一条 84% 就漏判了。

### ⚠️ 这道守卫的局限（如实说明）

压缩只能砍掉**更早**的行，而复读的恰恰是**最近**几条。
实测压到 24 行、16 行，那几段原文仍在保留范围内 → **判据仍会命中**。

所以它的实际作用是**把模仿池从 60KB 压到 11KB**（大幅削弱可供模仿的样本量），
**不是移除复读原文**。要真正移除，得压到 6 行左右，那会牺牲对话连续性 —— 没做。

## 五、顺带确认的另一个真 bug

会话 `f8e74dc4`（2026-09-01/02）：**0 条真人发言、64 条全是引擎注入**，
她的 64 条回复里 **52 条长度完全相同（360 字）**，63 对相邻回复中 49 对相似度 ≥95%。

**那不是模型复读，是同一条回复被重复投递** —— 与历史记录的 "welcome_back 投递 187 次"
是同一类 bug。所以「重复」在这个系统里有**两个独立来源**：

1. 生成层：模型对相似提问给出相似回复（15~24% 的基线）
2. 投递层：同一条回复被发出多次（引擎侧）

## 六、本轮落地的改动

| 改动 | 作用 |
|---|---|
| `scene/style.py` `find_duplicate()` | 发送前判重（一字不差、改一两个字都算） |
| `scene/style.py` `looks_like_repeating()` | 会话级复读检测（只算相似度，不打印内容） |
| `main.py` `apply_style_guard()` | 检出复读 → 压缩会话 |
| 模型 `local-v2` | `repeat_penalty` 1.08→1.15、加 `presence_penalty` 0.4 / `frequency_penalty` 0.3、`num_ctx` 32768→16384（缓解 swap 打满） |
| `SOUL.md`「别落进套路」 | 形式层规则（起手要换、别写排比、段数别固定） |
| `tools/style_analysis.py` | 纯数字体检，可随时复测（**默认不输出任何原文**） |

## 七、下一步（需要新数据）

现在**没有新的直聊样本**，无法验证守卫是否真的降低了复读率。等有人再聊时：

```bash
python3 tools/style_analysis.py            # 只看数字
python3 tools/style_analysis.py --trend    # 看是否随时间改善
```

若复读仍在，下一步应该试的是：**换更高精度的量化**（Q2_K → Q3_K_M/Q4_K_M）。
Q2_K 是极激进的量化，虽然**本轮数据没有证明它是复读主因**，
但它确实是"上下文跟随差、容易进入退化状态"的已知诱因，
而且 24GB 机器跑 Q3 是可行的（Q2 12GB → Q3 约 15GB）。

用轨迹文件（`*.trajectory.jsonl`）看**真实编译出来的上下文**，`context.compiled`
记录的 `data.messages[0]` 是：

```

         ### In Progress\n### Blocked\n\n## Key Decisions\n\n## Next Steps\n\n## Critical Context"
```

**这是一段角色扮演对话被压缩后的"记忆"：目标＝无、进展＝无、阻塞＝无，全文 297 字符、零信息量。**

它是**编程 agent 的摘要模板**（Goal / Progress / Next Steps），拿去总结"胡桃和旅行者聊天"
只能产出一堆 `(none)`。她此前那段对话的"记忆"就是"什么都没有" ——
这正是她"上下文完全不衔接"、只能靠人设套路回话的机制。

`context.compiled` 从 14:52 到 17:37 的每一条都带着它（43 条里 37 条有）。

## 二、两个"虚惊"要如实记下来（避免下次又误判）

| 我一度怀疑 | 实际 |
|---|---|
| OpenClaw 自带压缩把对话发去云端 DeepSeek 摘要（违反"敏感内容不出本机"） | **没有**。该会话 44 次 `model.completed` 全是 `provider=ollama, modelId=local`；`compactionCount` 全为 0 |

`maybe_compact_session` 读 `openclaw sessions --json` 的 `totalTokens` 来判断，
而该会话的 `totalTokens` 是 **None** → 函数在 `if not used` 处直接返回。
所以那个空摘要不是引擎造成的，是更早一次压缩留下的、此后一直挂在上下文里。

## 四、又一次没能复现

用**你完整的 88 条真实会话**（还原后的那份）+ 完整系统提示词，问一个全新问题：

```

```

即使用真实上下文，本地模型也没复读。**触发条件仍然未找到。**

## 五、本轮改动

# 第三轮：抓到"固定格式"的真身，并打通注入点

## 一、指标换对了，症状一眼可见

前两轮一直用"整条回复相似度"找复读——**指标太粗**。改成看**每条回复的开头形态**：

```
她最近 20 条回复：
  括号动作开头    20/20 = 100%
  同族身体反应    18/20（脸红×9、深吸气×4、整个人一顿×3、耳朵×2）
  不同开头只有    8 种
  最高频          「（脸瞬间」出现 5 次
```

**每一条都以「（动作）」开头，而且全是同一族身体反应。** 这正是用户说的
"每段一个模子、字一模一样"。

之前漏掉的原因：检测器用**精确字符串匹配**——`（脸瞬间红透` 与 `（脸瞬间红到`
就不算重复。改成**按语义族归类**（脸红/耳朵/深吸气/整个人一顿…）才抓到。

> 教训：**指标选错，症状就在眼前也看不见。** 前两轮"没复现"有一部分是
> 因为我在用错的尺子量。

## 二、OpenClaw 只注入固定清单的文件

实测各文件内容在 systemPrompt 里的**整行命中率**：

| 文件 | 命中 |
|---|---|
| SOUL.md | 168/168 |
| IDENTITY.md | 35/35 |
| USER.md | 21/21 |
| MEMORY.md | 40/40 |
| AGENTS.md | 70/70 |
| TOOLS.md | 11/11 |
| HEARTBEAT.md | **0/14** |
| 自定义 STYLE.md | **0/3** |

**自定义 .md 文件不会被注入。** 所以要让直聊那条链路（引擎完全绕过）
看见动态提醒，**只能写进那六个之一**。选 `MEMORY.md`（"她的记忆"）。

## 三、实现：安全注入 + 实测验证

`scene/style.py: update_style_block()`

- 只改 `<!-- AUTO:STYLE BEGIN -->` 与 `<!-- AUTO:STYLE END -->` 之间的内容
- **两个标记必须已存在；不存在就什么都不做** —— 绝不擅自改用户手写的文件结构
- 有回归用例守着这条（"无标记时不动文件"）

实测提醒真的进了 systemPrompt（29,910 字符，模型每次都能看到）：

```
## 说话方式提醒（引擎自动更新，每条都看一眼）
**最近我这几句话的开头重复得太多，这一条必须换个起法：**
- 我已经用过 20 次「（…）身体反应开头（脸红×9、深吸气×4、整个人一顿×3）」——别再用它开头
- 我已经用过 5 次「（脸瞬间」——别再用它开头
…
换法子的意思是：**动作、语气词、直接说事**这三条路换着走，别每段都先垫一个括号动作。
```

引擎每 20 轮自动刷新（`apply_style_digest`，默认开、非破坏性、幂等）。

## 四、顺带查实的两个环境事实

   与 **9,672 字符的 tools schema**。我的复现测试一直少了这两块。
2. 每条编译记录都带 `truncated: True, reason=trajectory-array-size-limit,

   且 `originalLength` 在 17:37 从 118 重置为 69，紧接着就是 17:46 的复读。

# 第四轮：把"提示词能不能治"这件事测死了

## 一、结论先说：**所有提示词/采样层面的干预都无效**

用**真实的 systemPrompt + 真实会话上下文**（29,910 字符）做的 A/B，指标是
"第一条消息是否以「（动作）」开头"：

| 干预 | 括号开头占比 | 样本量 |
|---|---|---|
| **基线（现状）** | **98%** | 42 |
| MEMORY.md 提醒 —— 第一版「别重复这些开头」 | 100% | 8 |
| MEMORY.md 提醒 —— 第二版「禁止括号放开头」 | 80% → 复查 100% | 5 / 8 |
| MEMORY.md 提醒 —— 第三版「只改开头、别少说话」 | 100% | 8 |
| 采样参数 `presence_penalty` 0.4 + `frequency_penalty` 0.3 + `repeat_penalty` 1.15 | 100% | 5 |
| 「点名你在模仿自己」的强指令 | **100%** | **12** |

第二版那次 80% 是**噪声**——同样措辞在 n=8 时又是 100%。
**唯一有效的是把她的回复从上下文里拿掉：100% → 50%（n=4）。**

## 二、其中的教训（我犯的错）

1. **n=5 得出的"有效"完全不可信。** 第二版拿到 80% 时我以为成了，
   还把这条写进了提交信息。n=8 复查后翻盘。
   → 以后这种 A/B **至少 n≥12** 才下结论，且要能复现。
2. **第二版还引入了副作用**：我写了"大部分回复一个括号都不要有"，
   有一条回复变成了 `NO_REPLY`（OpenClaw 的"无话可说"标记）——**那会让她变哑巴**，
   比模板化严重得多。已改掉，但这也说明：**改人格输出时，副作用比正效应更危险。**

## 三、机制确认：驱动因素是"她模仿她自己"

| 上下文 | 括号开头占比 |
|---|---|
| **不含**她的历史回复 | **50%** |
| **含**她的历史回复 | **100%** |

而且去掉范例后，输出**正是我们想要的形态**——动作挪到句中或句尾：

```
哼，本堂主今天嘛……（打了个哈欠）
诶哟，刚才还在说那种事呢～现在突然问起港里人了？（眯…
```

## 四、这个结果把嫌疑指向了模型本身

**模型的指令遵循能力是这个瓶颈**：一条写在系统提示词里、
措辞强到"看到自己前面这么写，你偏不这么写"的指令，12 次生成**一次都没被遵守**。
这符合**极低比特量化（Q2_K）**导致指令遵循退化的特征——
前面几轮我把它当假设排除过，现在它成了**最有证据支持的方向**。

## 五、当前处置

- `style_digest` **默认关**（实测无效），代码保留并注明结论
- `MEMORY.md` **已还原为原样**（撤掉提醒块）——不为无效的机制改用户的文件
- 采样参数 `local-v2` 保留作备选，但**未切换到它**（实测无差别）

## 六、下一步的两条路（需要用户决定）

1. **换更高精度的量化**（Q2_K → Q3_K_M，12GB → 约 15GB，24GB 机器可行）。
   现在这个方向有了实证依据：模型连强指令都不遵守，而 Q2_K 是最低质量的量化档。
2. **减少上下文里她自己的回复**（唯一被证明有效的干预：100% → 50%）。
   代价是对话连续性——这需要用户权衡。

**在两者之间，我建议先试 ①**：它不动对话历史、不影响连续性，
而且如果模型指令遵循能力本来就差，② 也只是绕过症状。

# 第五轮：量化也排除了

## 实验

从 ModelScope 下载 `unsloth/Qwen3.5-35B-A3B-GGUF` 的 **UD-Q3_K_XL**（16.6GB，
与当前 `UD-Q2_K_XL` 同系列上一档），建了平行模型 `local-q3`，
**参数与 `local` 完全一致**（只变量化档），用**同一份真实 systemPrompt + 同一份真实上下文**
做同样的 A/B：

| 模型 | 量化 | 括号开头占比 | n |
|---|---|---|---|
| `local` | Q2_K | **88%** | 8 |
| `local-q3` | Q3_K_M | **100%** | 8 |

**没有改善。** 精度翻一档（12.2GB → 16.6GB）对这个行为**毫无影响**。

下载本身是干净通过的：16,601,176,704 字节，与期望**逐字节一致**，
用 `pget_verified.py`（带逐段校验）耗时 962 秒、约 15 MB/s。

> 至此被实验排除的假设清单：Q2_K 量化、num_ctx 过大、Modelfile 模板拍平、
> 采样参数（repeat/presence/frequency penalty）、系统提示词过长、
> **以及所有提示词层面的干预**。

## 唯一剩下的解释：上下文里的"她自己"

| 条件 | 括号开头 |
|---|---|
| 上下文**含**她的历史回复 | **88~100%** |
| 上下文**不含**她的历史回复 | **50%** |

她的 32 条历史回复**全部**以「（动作）」开头。模型在延续这个模式，
而且**任何文字指令都改不动它**——这正是 few-shot 示例压过指令的典型表现。

## 三条可选路径（需要用户决定，代价不同）

**A. 只清掉会话里她的回复（最有效，代价最大）**
实测能把 100% 压到 50%。做法是让引擎改写会话转录里她的回复，
把开头的括号动作去掉（**注意：微信里的历史消息不受影响**，
会话 `.jsonl` 只是给模型看的上下文）。
→ 缺点：动了 OpenClaw 拥有的文件，需要做好备份与回滚。

**B. 压缩会话（`--max-lines` 截断）**
让引擎在会话变长时截断，减少可供模仿的样本数。
→ 缺点：丢对话连续性；而且实测截到 16 行时**那几段复读原文仍在保留范围内**。

**C. 接受它，改从产品层缓解**
比如接受"她的风格就是每条带动作"（这本身是人设的一部分），
转而只在**重复度**上设限（同一条回复内不许出现两个同族动作）。
→ 缺点：治标，但不动数据、风险最低。

# 第七轮：改写**确实有效**，但"固定开头"只是换了个形式

## 一、端到端测试踩的坑（先说，避免误判）

我建了个临时会话键、把**改写后**的转录复制过去想端到端验证——
**OpenClaw 会无视预注册的 sessionId、自己新建会话**（试了两次，都把我写的 id 换掉）。
所以第一次端到端测出的 100% **测的是一个全新空会话，不是改写效果**。
（临时会话键与文件已清理；生产键 `…weixin:direct:YOUR_ACCOUNT` 与 93 行会话完好。）

## 二、用真实条件测，改写是有效的

把**改写后的生产会话**当上下文（她 20 条回复里 0 条以括号开头）
＋ **真实 systemPrompt（29,910 字符）**：

| 条件 | 括号开头 |
|---|---|
| A 原 SOUL.md 示例 | **12%** (1/8) |
| B 改示例（动作不在开头） | **0%** (0/8) |

对比改写前同条件的 **100%** —— **改写把括号开头从 100% 压到 12%**。

## 三、⚠️ 但出现了一个新问题，必须如实说

她换了另一个套路：**8/8 全部以「……」开头**。

```
……心情？    ……忙？    ……天气？    ……晚上？
……哎哟，你这一问，本堂主还真得好好想想。
……（轻轻戳了戳你的额头）
```

**"每条都用同一个套路开头"这件事没有消失，只是从「（动作）」变成了「……」。**
这解释了为什么用户最初描述的是"固定的格式"——**根子在"开头必有公式"，不在具体是哪个公式**。

## 四、顺带发现的第二个驱动源：SOUL.md 的**示例**

原来那段是：

```
**【动作神态】** …用全角括号括起来，像这样：
> （叉腰）
> 谁说我往生堂晦气？
> （眯着眼笑）你躺进去试试
> （叹气）钟离先生又忘了带钱
```

**三个示例全部把动作放在行首**，而正文规则说"写在句首或句尾都行"。
**模型学的是示例，不是规则**——和"她自己历史"是同一种失败模式。

已把示例改成动作**不在开头**：

```
> 谁说我往生堂晦气？（叉腰）
> 你躺进去试试，本堂主眯着眼笑你呢
> 钟离先生又忘了带钱——本堂主这个月替他垫第三回了（叹气）
```

并把「写在句首或句尾都行」改成「写在句子中间或句尾」，
补一条「括号不许放句首」，消掉原来的自相矛盾。

## 五、结论与下一步

**根因（现在可以下的结论）**：这个模型对"开头"有很强的公式化倾向。
具体公式是什么（`（动作）` 还是 `……`）取决于上下文与示例，
**但"每条都要用同一个公式开头"这一点不变**，而且**任何文字规则都压不住它**
（12 轮强指令 A/B 全无效、采样参数无效、量化无效）。

**已落地的两条**：
1. `tools/style_rewrite.py`：周期性去掉历史回复开头的括号（100% → 12%）
2. SOUL.md 示例改成动作不在开头（12% → 0%，n=8 偏小但方向与机制一致）

**下一步要盯的**：等她下次开口，看新开的头是不是从 `（…）` 换成了 `……`。
如果是，说明**还得继续换"种子"**——比如让引擎周期性把历史回复的**多种**开头形式
都改掉（不只括号），或者干脆接受"她有自己的口癖"这个人设特征。

# 第八轮：结论修正 —— 模板一直是**两段式**，而且剥离只是让公式搬家

## 一、修正上一轮的结论（我上轮说错了）

上轮我说"她换了个套路，从（动作）变成……"。**核对备份后，这个说法不准确。**

| | 改写前 | 只剥括号后 |
|---|---|---|
| 以（动作）开头 | 88% | 0% |
| 以「……」开头 | **0%** | 69% |
| **剥掉括号后紧跟「……」** | **69%** | 69% |

**「……」的套路一直都在（69%），只是被括号挡在前面。** 她的模板一直是两段式：

```
（叉腰）……哼，巧了。
（抬头看你一眼）……在呢，宝宝。
```

上轮我只剥了前半段，等于把后半段**露出来**了——不是换了套路，是**露出来了**。

## 二、已把两段一起剥

`strip_leading_actions()` 现在同时剥括号动作与行首省略号（最多连剥 4 层）。
生产会话再改 33 条，现在 **48 条回复：0 括号、0 省略号**。

## 三、但效果**不稳定**，必须如实说

| 测试条件 | 括号开头 |
|---|---|
| 改写前（基线） | 98~100% |
| 只剥括号，上下文取最近 40 条 | **12%** (n=8) |
| 两段都剥，上下文取全部 88 条 | **63%** (n=8) |

差异可能来自上下文条数（48 条她的回复 vs 20 条）——**范例越多，风格拉力越强**。
而且这一轮出现了新形态：`今天心情嘛……`（省略号跑到**句尾**去了）。

## 四、八轮下来能站住的结论

**这个模型对"开头"有极强的公式化倾向，而且换不掉。**

- 提示词：12 次强指令 A/B，**全无效**
- 采样参数（repeat/presence/frequency penalty）：**无效**
- 量化（Q2_K → Q3_K_M）：**无效**
- 改写上下文：**有效但不稳定**（12%~63%），而且**公式会搬家**
  （括号 → 省略号 → 又回括号，甚至跑到句尾）

**"每条都用同一个公式开头"这件事，是模型层面的特征，不是配置能治的。**
如果要彻底解决，方向不是继续调参，而是**换个模型**（更大/更高精度/不同家族），
或者**接受它当口癖**——`今天心情嘛……` 这种读起来其实比 `（脸瞬间红透）` 自然得多。

## 五、当前处置

- 两段剥离保留在 `tools/style_rewrite.py`，引擎周期性维护
- 回滚：`python3 tools/style_rewrite.py --restore`
- 备份另存：`logs/session-before-style-rewrite.jsonl`、`logs/session-before-ellipsis-strip.jsonl`
