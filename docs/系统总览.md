# 系统总览 —— 胡桃 · 璃月港数字化场景

> 本文是整份方案的地图。先读这里，再按需跳转各专题文档。
> 一句话定位：**纯逻辑的场景状态机**（无图形、无 3D）产生随机事件，
> 喂给**本地 OpenClaw 角色 agent（胡桃）**，由她**主动**以转述口吻分享见闻，
> 并可顺带生图、上 Live2D、切换云端/本地模型。

---

## 1. 它是什么、不是什么

| 维度 | 说明 |
|---|---|
| **是** | 事件驱动的 AI 虚拟角色**主动发言**系统；场景是"数字化场景"，靠状态机与随机事件表达，**不画图、不建模** |
| **不是** | 聊天机器人（一问一答）；3D/图形化场景；游戏 |
| **主动性从哪来** | 引擎决策器判断"该不该说话"（时机），OpenClaw 生成"说什么"（内容） |
| **时间锚点** | UTC+8 真实时间：胡桃按作息（晨起/工作/午饭/晚间出殡/深夜休息）生活 |
| **叙事纪律** | 她**转述/分享**场景见闻，不是"扮演 NPC 对用户说台词"；不出现"屏幕/手机/消息"等现代器物 |

## 3. 架构分层

```
┌─ 场景层（scene/，纯 Python 标准库，无第三方依赖）
│    state      场景状态：day/hour/weather/location/affinity/present/receipts，原子持久化
│    engine     主循环：时钟推进 → 天气演化 → NPC 在场 → 事件生成 → 防沉默 → 对话缓冲闸
│    events     事件模板加载（JSON/YAML）+ 条件匹配 + 概率抽取
│    filters    相关性过滤（睡觉不打扰等）
│    decision   主动发言决策（勿扰/最小间隔/主动度/概率门/对话缓冲/见闻静默）
│    delivery   投递通道（sessions / pending / webhook / json_file / console）
│    receipts   回执回环：OpenClaw 处理结果反哺（冷却/续聊）
│    actions    动作记忆：身体动作跨回复连贯，不重复、不矛盾
│    memory     关键词记忆：投递前注入近期话题，替代携带完整历史
│    style      说话风格去模板化（形状记忆，不读内容）
│    news       原神官方资讯 → 世界内"传闻"事件
│    imagery    图片文件完整性校验
│    security   意外发送者监测告警（不拦截）
│    openclaw_sync  亲密度 → 云/本模型切换（键级合并，不整数组重写）
└─ 入口与运维
     main.py          引擎入口（--once 演示 / 常驻守护 + 自愈 + 周期巡检）
     log_server.py    运行日志 WebUI（纯标准库，127.0.0.1:8620）
     tools/           20+ 运维/功能脚本（见 §7）
     live2d/          VTube Studio 桥接
     persona/         人设快照（SOUL/IDENTITY/USER/MEMORY 模板）
     cast.json        角色库（身份认知反差 + 在场规则）
     events.json      事件模板库（47+，含作息/饭点/出殡对齐）
     config*.json     引擎配置（默认 / heartbeat / live2d / sessions 生产 / webhook 示例）
```

## 4. 一次 tick 的数据流（端到端）

```
tick()  ──► 时钟推进(sync_to_utc8) ──► 天气演化 ──► 好感度衰减 ──► NPC 在场演化
   │
   ├─ 对话缓冲闸（任一方最近开口 N 分钟内 → 一条主动事件都不产生，直接返回）
   │
   └─ 事件生成（一次 tick 至多一个；见闻带 news 标签再压 news_hold_minutes）
         │
         ├─ 相关性过滤（filters）── 不相关 → 丢弃
         │
         ├─ 决策器（decision：勿扰/间隔/主动度/概率门）
         │
         ├─ 投递（delivery：按通道顺序，失败降级到下一通道）
         │     ├─ sessions    openclaw agent --deliver（生产主链路）
         │     ├─ pending     心跳读 pending.json
         │     └─ webhook     Gateway Hooks /hooks/agent（Bearer 鉴权）
         │
         └─ 回执（receipts）：成功/失败/过期 → 反哺冷却与续聊
                ▲
                └─ 投递失败或相关性拒绝时：状态快照回滚（冷却/好感度不扣）
```

**一个关键不变量**：投递失败或被拒绝的事件，其冷却与好感度**不生效**（引擎 `_snapshot`/`rollback`/`commit` 三态）。
否则"被决策层挡下的事件已扣冷却"会把 3~7 天冷一次的长冷却事件永久丢掉。

## 5. 云 ↔ 本地模型切换 + 记忆同步

| 项 | 值（默认，可在 `config.sessions.json` 调整） |
|---|---|
| 判据 | `_pick_chat_model()`（`scene/delivery.py`）：本地侧 `ollama/local`，云端侧 `cfg.model`（当前 `deepseek/deepseek-v4-flash`） |
| 上行（云→本） | `close` 档 **且** 亲密度 ≥ 95 → 切 `ollama/local` |
| 下行（本→云） | 亲密度 ≤ 88 → 切回云端（`deepseek/deepseek-v4-flash`） |
| 88~95 | 保持现状（**滞回**，防抖动） |
| 亲密度衰减 | `affinity.decay_after_idle_hours`（默认 6h 空闲后开始）、`rate_per_hour`（0.002 ≈ 4.2 天跌破 95） |
| 两条链路同源 | **主动消息**（`delivery.py` 用 `--model` 直接指定）与**用户直聊**（`main.py sync_chat_model` → `openclaw_sync.sync_agent_model` 写 `model.primary`）共用同一判据，避免两边各用各的模型 |
| 记忆同步 | `scene/openclaw_sync.py` 用**键级合并**改 `~/.openclaw/openclaw.json`，绝不整数组重写（避免抹掉其他工作区的键） |

> 注：配置里的 `model_local.cloud_model`（`moonshot/kimi-k2.6`）字段保留，但引擎路由的云端侧实际取
> `cfg.model`（`deepseek/deepseek-v4-flash`）；要换成 kimi，需把两处都改成同一个模型名。
> 直聊是否随亲密度切云由 `model_local.sync_openclaw`（默认 `true`）控制；若要求"直聊永远本地不出机"，
> 设 `sync_openclaw: false` 并把 agent `main` 的 `model.primary` 手动钉在 `ollama/local`。
>
> 判断模型是否被降级**只看 `model.fallback_step` 轨迹事件**，别用会话里的 `message.model`。

## 9. 关键机制速查（一句话各一）

- **UTC+8 同步**：`sync_to_utc8` 把场景时钟锚定北京时间；`scene_minutes = day*1440 + hour*60`。
- **好感度档位**：`stranger 0-29 / familiar 30-69 / close 70-100`（`AFFINITY_TIERS`）。
- **防沉默**：`anti_silence_minutes` 无事件则强制日常闲聊；`follow_up_minutes` 话题续聊。
- **对话缓冲**：任一方最近开口后 N 分钟内零主动事件（**不看 priority**）；见闻再压 `news_hold_minutes`。
- **动作连贯**：`actions.py` 记录已发生的身体动作，杜绝"上一段刚摘帽、这一段又摘帽"。
- **说话去模板**：`style.py` 记"形状"不记内容；`style_rewrite.py` 周期性剥离历史回复开头的 `（动作）`/省略号。
- **间接引语**：事件指令要求转述/分享口吻 + 邀请回应，非"角色对用户说台词"。
- **安全**：白名单监测（告警不拦截），token 文件按模式匹配 + 状态自检。
