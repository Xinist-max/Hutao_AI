# 高可用 AI 虚拟角色构建方案

> 版本：v1.1　适用范围：以本地部署为主、可平滑扩展到云端的 AI 虚拟角色（示例角色：胡桃）
> 六大需求：①心理表情变化的自然语言对话　②已训练 LLM 开口说话　③向用户展示图片　④Live2D 等强可视化表现　⑤调用本地按角色训练好的 OpenClaw　⑥数字化场景程序（非图形建模）按角色关系等条件随机向 OpenClaw 反馈事件、驱动主动发言

---

## 1. 总体架构

采用**分层 + 事件总线**架构，各模块独立成进程/服务，通过统一消息协议解耦，保证"可用性强"（局部故障可降级、模块可插拔、可热更新）。

```
┌─────────────────────────── 表现层 (Web / 桌面) ───────────────────────────┐
│  Live2D 渲染    氛围背景(可选)     图片展示      语音播放     聊天气泡/UI    │
│  (pixi-live2d)  (HTML/CSS)     (img 卡片)    (WebAudio)   (Vue/React)    │
└──────────────▲──────────────────────────────────────────────▲───────────┘
               │ 统一消息协议 (WebSocket / HTTP)                │
┌──────────────┴──────────────── 交互编排层 ───────────────────┴───────────┐
│  Orchestrator：对话状态机 · 情绪状态机(PAD) · 记忆管理 · 事件调度器 · 降级链 │
└──────┬─────────────────┬──────────────────┬──────────────────┬──────────┘
       │                 │                  │                  │
┌──────▼─────┐   ┌───────▼────────┐  ┌──────▼────────┐  ┌──────▼─────────┐
│ 智能层 Brain│   │ 能力层 Capability│  │ 本地角色模型    │  │ 场景层 Scene    │
│ 主对话LLM   │   │ TTS/STT        │  │ 本地 OpenClaw  │  │ 场景模拟引擎     │
│ 情绪解析    │   │ 图片生成/检索   │  │ (角色实例)      │  │ 状态机+事件生成     │
│ 工具调用    │   │ RAG 检索       │  │ 或微调角色LLM   │  │ 关系/条件过滤  │
└────────────┘   └────────────────┘  └───────────────┘  └─────────────────┘
```

**模块职责速览**

| 模块 | 职责 | 关键技术选型（开源优先） |
|---|---|---|
| 主对话 LLM | 生成角色台词 | 本地微调模型：Qwen2.5-7B/14B、GLM-4-9B、Llama-3.1-8B；推理服务 vLLM / Ollama / llama.cpp（统一 OpenAI 兼容 API） |
| 情绪引擎 | 心理状态建模与表情驱动 | PAD 三维情绪模型 + 情绪状态机 + 好感度系统 |
| 记忆系统 | 短期对话 / 长期记忆 / 重要事件 | 向量库 Chroma / FAISS + SQLite 事件日志 |
| TTS | 让角色"开口说话" | GPT-SoVITS（5 秒音色克隆）、CosyVoice 2、Fish-Speech、ChatTTS；可选 RVC 音色转换 |
| STT（可选） | 语音对话 | Whisper / FunASR 本地部署 |
| Live2D | 可视化表现 | Live2D Cubism SDK for Web：pixi-live2d-display / oh-my-live2d |
| 图片能力 | 展示 / 生成图片 | 预置图库 + CLIP 语义检索；ComfyUI API + SDXL + 角色 LoRA 动态生成 |
| 本地角色模型 | 调用角色化 OpenClaw | OpenClaw 本地实例（角色化配置），或 LLaMA-Factory 微调的角色 LoRA/全参模型 |
| 虚拟场景（数字化） | 逻辑场景状态机 + 随机事件生成，**无图形建模** | Python/TS 编写的模拟程序；事件模板配置（YAML/JSON）；按时间/天气/角色关系等条件随机触发，事件反馈给 OpenClaw |

## 2. 需求①：含心理表情变化的自然语言对话

**核心思路：LLM 生成"台词 + 情绪标签"双通道输出，由情绪引擎维护连续的心理状态，前端据此驱动表情。**

### 2.1 人物设定固化（角色卡）
- 采用 **SillyTavern Character Card V2** 格式定义角色：姓名、人设、说话风格、口头禅、禁忌、背景故事、示例对话。
- 角色卡转成 system prompt 注入主对话 LLM；修改角色只需换卡，**无需重训模型**（可用 [SillyTavern-Character-Creator](https://github.com/bmen25124/SillyTavern-Character-Creator) 半自动生成）。

### 2.2 情绪引擎（心理表情变化的核心）
采用 **PAD 三维情绪模型**（愉悦度 P / 激活度 A / 支配度 D）+ 情绪状态机：

- **情绪状态机**：定义若干离散情绪态（喜悦、生气、害羞、惊讶、难过、平静……），每态绑定 Live2D 表情/动作与语音语调参数。
- **PAD 连续空间**：LLM 输出的情绪标签 → 映射到 PAD 坐标；情绪随对话内容、事件、时间自然**衰减/迁移**（如被夸奖 → P↑，被冒犯 → P↓D↑，暧昧 → P↑A↑）。
- **人格参数**：OCEAN 大五人格（开放性、尽责性、外向性、宜人性、神经质）影响情绪阈值与回复风格，让心理变化"有个性"。
- **好感度系统**：长期累积的亲密度/好感度，改变角色的亲近程度、话题权限、称呼方式——这是"心理变化"的长期维度。
- **事件驱动**：虚拟场景随机事件（见 §7）直接注入情绪引擎，形成"事件 → 情绪迁移 → 表情/台词联动"。

### 2.3 输出协议（双通道）
对话 LLM 的输出采用结构化格式，由编排层解析：

```
{
  "text": "今天的月色真美呀，旅行者～",       // 角色台词
  "emotion": {"type": "joy", "p": 0.8, "a": 0.6, "d": 0.5},  // 情绪标签
  "action": "look_at_user",                    // 动作指令（可选）
  "image": null,                               // 配图指令（可选，见 §4）
  "memory_flag": "important"                   // 是否写入长期记忆（可选）
}
```

- 实现方式：在 system prompt 中要求模型按 JSON 输出（或用函数调用/受约束生成如 vLLM guided decoding），文本流式给前端，情绪标签先到先驱动表情。
- **降级**：模型不输出合法 JSON 时，用正则提取 `(开心)` `(生气)` 等简易标签或默认"平静"。

### 2.4 记忆系统
- **短期**：最近 N 轮对话原文。
- **长期**：关键信息（用户喜好、约定、角色经历）经 embedding 入向量库，对话前做 top-k 检索注入上下文（RAG）。
- **事件日志**：重要事件（含场景事件）写入 SQLite，供复盘与情绪引擎引用。

## 3. 需求②：用已训练好的 LLM 开口说话

### 3.1 对话侧（Brain）
- 首选本地推理：**vLLM**（高吞吐）或 **Ollama / llama.cpp**（易部署），统一暴露 OpenAI 兼容 `/v1/chat/completions`。
- 角色化两条路线：
  - **零训练路线（推荐起步）**：通用模型 + 角色卡 prompt + RAG，几天内上线；
  - **微调路线**：用 [LLaMA-Factory](https://github.com/hiyouga/LLaMA-Factory) 在角色对话语料上 LoRA/QLoRA 微调（7B 单卡 24G 可训），产出角色 LoRA 挂载到基座模型。

### 3.2 语音侧（TTS 开口说话）
- **音色**：GPT-SoVITS 只需角色 5 秒~1 分钟干声即可克隆音色，效果自然，本地可跑；备选 CosyVoice 2（情感控制强）、Fish-Speech（速度快）、ChatTTS（对话式自然）。
- **流程**：编排层拿到台词 → 调用 TTS 服务合成音频 → 前端 WebAudio 流式播放；同时把音频回传 Live2D 做**口型同步**（viseme 映射到模型参数，或按音量包络驱动嘴部）。
- **降级链**：GPT-SoVITS 失败 → 系统语音（Edge-TTS 在线/内置合成）；再失败 → 纯文字气泡，不打断对话。
- 语音对话闭环（可选）：FunASR/Whisper 本地识别用户语音 → 文本进对话管线。

## 4. 需求③：向用户展示图片

图片作为**独立消息类型**在统一协议中传输，前端以卡片形式展示：

| 方式 | 实现 | 适用 |
|---|---|---|
| 预置图库 | 角色立绘、表情差分、CG、场景图本地资产库 | 零成本、快、离线可用 |
| 语义检索 | 对话内容经 CLIP 模型编码，在图片库做向量检索 | 让展示内容"贴题" |
| 动态生成 | 编排层调用 ComfyUI API + SDXL + 角色 LoRA，按台词/场景提示词生图 | 无限新图、配合剧情 |
| 氛围配图（可选） | 按场景状态（天气/时段）从图库选氛围图 | 无图形场景时仍能给用户"场景感" |

- 触发方式：① LLM 输出带 `image` 字段（如"给你看我家院子"→ 返回场景图）；② 场景事件自动推送（如"下雨了"→ 推送雨景图）；③ 用户主动请求（"画一张你穿新衣服的样子"→ ComfyUI 生成）。
- 异步处理：生图耗时较长，先回文字"等一下哦～"再推送图片，避免卡顿。

## 5. 需求④：Live2D 等强可视化表现

### 5.1 首选：Web 端 Live2D
- **渲染库**：pixi-live2d-display 或 oh-my-live2d（基于 Live2D Cubism SDK for Web，支持 Cubism 2/4 模型，开源免费非商用）。
- **模型来源**：官方/商业 Live2D 模型，或美术自绘后经 **Cubism Editor** 制作；模型需带表情参数（eye、mouth、brow、body 等）。
- **表情驱动**：维护"情绪标签 ↔ Live2D 参数"映射表（如 joy → 嘴角上扬 + 眯眼 + 头微仰），情绪引擎每帧计算目标参数并平滑插值（Lerp），实现自然过渡。
- **常驻行为**：idle 呼吸/眨眼/视线随机游走、鼠标跟随视线、点击/触摸交互。
- **口型**：TTS 音频驱动（见 §3.2）。
- 参考开源整包：[Live2D-LLM-Chat](https://github.com/suzuran0y/live2d-llm-chat)（Live2D+ASR+LLM+TTS 实时对话）、[handcrafted-persona-engine](https://github.com/elevenyellow/handcrafted-persona-engine)（Live2D+LLM+ASR+TTS+RVC）。

### 5.2 备选/进阶表现
| 场景 | 方案 |
|---|---|
| 直播/桌面 | VTube Studio + 虚拟摄像头（配合 OBS），Live2D 由本工具驱动 |
| 3D 立绘 | VRM 模型 + three-vrm（Web）/ Unity + VTuber 预制件（桌面/VR） |
| 增强真实感 | 表情/口型用 RVC 音色 + Live2D 微表情关键帧；身体动作用动作捕捉（MediaPipe 单目捕捉，可选） |

## 6. 需求⑤：调用本地按角色训练好的 OpenClaw

**说明**：OpenClaw 是开源、可本地部署的个人 AI 助手框架（"Your own personal AI assistant. Any OS. Any Platform."），本身不是微调框架，但可以通过**角色化配置**（人设文档、知识文件、记忆、工具权限）把实例固化为特定角色。"按角色训练好"的本地 OpenClaw 即：跑在本地、加载了该角色人设与记忆的 OpenClaw 实例。

### 6.1 三种对接模式（可组合）

| 模式 | 做法 | 适用 |
|---|---|---|
| **A. 角色脑模式（推荐）** | 编排层的"主对话"路由到本地 OpenClaw 实例：把用户输入作为任务交给 OpenClaw（其内部按角色人设 + 记忆 + 工具执行），取回输出文本/情绪标签进统一协议 | 想复用 OpenClaw 的记忆、工具与角色文件能力 |
| **B. 知识/记忆注入模式** | 只把 OpenClaw 的角色人设、知识库、记忆文件（如 persona 文档、长期记忆库）导出为 RAG 语料，注入主对话 LLM | OpenClaw 只作"资料库"，对话仍由自选 LLM 驱动 |
| **C. 工具执行模式** | 主对话 LLM 通过 function-calling 把特定任务（查资料、执行脚本、管理日程）委托给 OpenClaw，结果回填到对话上下文 | 角色需要"真做事"能力 |

### 6.2 工程接入要点
- **进程隔离**：OpenClaw 以独立服务/CLI 常驻进程运行，编排层通过其 API/命令行接口调用，超时与失败降级到主对话 LLM（不让角色"哑掉"）。
- **角色一致性**：OpenClaw 实例的人设文件与主对话 LLM 的角色卡保持同一份"角色定义"（单一事实源，双端同步），避免人格漂移。
- **情绪标签**：OpenClaw 输出通常无结构化情绪字段，由编排层追加一个轻量情绪分类（可用小模型或规则）补上 `emotion` 字段，保证前端表情链路一致。

> 若"OpenClaw"实指其他角色微调产物（如本地微调的角色模型服务），同样适用：任何暴露 OpenAI 兼容 API 的本地角色模型都可直接作为 Brain 接入，改动只在编排层配置一个 base_url。

## 7. 需求⑥：数字化场景模拟 + 随机事件主动反馈（无图形建模）

**定义（重要）**：此处的"场景"是**纯逻辑的数字化场景**——一个用编程语言实现的场景模拟程序，**不需要任何图形或 3D 建模**。它维护场景状态（时间、天气、地点、角色关系等），按条件**随机生成事件**，把"对角色有影响"的事件反馈给本地 OpenClaw，驱动角色**主动向用户发送文本**，实现"非一问一答"的主动对话模式。

### 7.1 场景 = 逻辑状态 + 演化规则
- 场景就是一组**场景状态** + 状态演化规则 + **事件生成器**，全部由代码与配置实现，没有图形。
- 场景状态示例：
  - **时间**：游戏内日期/时刻（可映射真实时钟）；
  - **天气**：晴 / 多云 / 小雨 / 雪 / 风…（随机演化）；
  - **地点**：角色与用户当前所在位置（如"院子 / 堂内 / 街上"）；
  - **角色状态**：空闲 / 忙碌 / 睡觉 / 外出；
  - **关系状态**：好感度、信任度、亲密度（数值 + 档位：陌生 / 熟悉 / 亲密 / 闹别扭）；
  - **氛围与日程**：节日、特殊日期、剧情进度、事件冷却表。

### 7.2 程序结构（纯代码实现）
```
scene/
  state.py     # 场景状态数据结构 + 持久化（JSON/SQLite）
  engine.py    # 主循环 tick()：推进时间/天气，评估条件，产出事件
  events.yaml  # 事件模板库：条件 / 概率权重 / 内容 / 对关系的影响（热加载）
  filters.py   # 相关性过滤：只保留"对角色有影响"的事件
orchestrator/  # 编排层：事件 → 主动发言决策器 → 注入 OpenClaw → 推送
```
- 实现语言：**Python（推荐，与 LLM/TTS 生态同栈）**，或 TypeScript（与前端同栈）。
- 运行方式：独立进程按固定节拍（如每 30 秒）执行 `tick()`；也可由事件驱动（用户发消息、定时器、手动触发）。

### 7.3 随机事件生成（按角色关系等条件）
```
事件模板库（条件 + 概率权重 + 描述 + 影响）
        │ tick() 逐条评估
        ▼
条件评估：时间 / 天气 / 地点 / 角色状态 / 好感度档位 / 冷却
        │ 命中且随机数通过
        ▼
事件实例化 ──► 相关性过滤 ──► 主动发言决策器 ──► 注入 OpenClaw（见 7.4）
```
- **关系条件示例**（需求⑥ 的"按特定角色关系等条件"）：
  - 好感度 < 30：仅基础问候/天气事件，主动发言克制；
  - 30 ~ 70：解锁天气、趣事、日常分享类事件；
  - > 70：解锁亲密事件（分享心事、邀请、玩笑、关心/吃醋），主动频率上调；
  - 特殊档位（如"闹别扭"）：触发道歉/和好类事件。
- **事件类型**：环境事件（天气/时段变化）、时间事件（深夜、节日、纪念日）、关系事件（好感度门槛解锁）、随机彩蛋（低概率惊喜）、用户状态事件（长时间无操作 → "想念/等待"类事件；刚登录 → 欢迎事件）。
- **影响闭环**：事件不只被反馈，还会反作用于场景状态（触发后进入冷却；部分事件 ± 好感度），形成"关系 → 事件 → 主动发言 → 对话 → 关系"的长期循环。
- **LLM 增强（可选）**：事件模板只给骨架，具体台词由 OpenClaw 以角色身份现写，保证每次随机且贴合人设。

### 7.4 主动发言机制（事件 → OpenClaw → 主动推送）

**目标**：把"用户提问 → 角色回答"的一问一答模式，升级为"角色有感知、会主动开口"的主动模式。

**完整链路**：

```
场景模拟引擎 tick() / 用户操作 / 定时器
        │ 产生事件
        ▼
事件总线 ──► 相关性过滤器（只保留"对角色有影响"的事件）
        │ stimulus（场景刺激）
        ▼
主动发言决策器
   ├─ 规则层：冷却、频率上限、勿扰时段、用户活跃度、好感度门槛、主动度参数
   └─ 语义层（可选）：小模型判断"此情此景角色是否值得主动开口"
        │ 决策 = 该说
        ▼
注入本地 OpenClaw（角色脑模式）──► 产出主动台词 + 情绪标签
        │
        ▼
统一协议推送：气泡文本 + 表情驱动 + TTS 语音（+ 可选氛围图）
```

**主动性的主体划分（重要设计原则）**：*时机判断*（什么时候该说）由编排层的主动发言决策器负责；*内容生成*（说什么、什么语气）由本地 OpenClaw（角色脑）负责。OpenClaw 是被唤起型框架，本身不会主动发消息，"主动"由我们的事件驱动循环来实现——决策器决定说，OpenClaw 决定怎么说。

**刺激注入格式（喂给 OpenClaw 的输入，示意）**：

```jsonc
{
  "role": "scene_event",
  "event": { "type": "weather_change", "to": "rain", "time": "23:10", "place": "院子" },
  "state": { "weather": "rain", "hour": 23, "location": "yard", "affinity": 72 },
  "instruction": "你正独自坐在院子里的石凳上，雨突然下起来了。"
                 "请以角色身份主动对用户说点什么，不要等待用户回复。"
}
```

**相关性过滤（只把"对角色有影响"的事件反馈给 OpenClaw）**：
- 空间相关：事件地点与角色所在/可见区域匹配（在屋里就感知不到院子下雨）；
- 人设相关：事件与角色身份/当前活动/在意的事相关（如胡桃在意生意与顾客、喜欢热闹与怪谈）；
- 关系门槛：好感度档位不足的事件直接丢弃（防止"亲密事件"过早出现）；
- 去重：同类事件在冷却期内不重复触发。

**克制与防打扰（可用性的关键）**：
- 频率上限（如 10 分钟内主动发言 ≤ 2 次）、单事件冷却；
- 勿扰时段（如深夜降低主动频率）、用户正在输入/连续追问时不插嘴；
- 可调"主动度"参数（克制 / 均衡 / 活泼），供不同场景切换。

**降级**：OpenClaw 不可用时，由主对话 LLM 以同一角色卡身份代答同一刺激，链路不断。

**完整示例走查（雨水事件）**：

1. 场景：璃月港夜色中的小院，23:10，天气状态由"多云"变为"小雨"，角色坐在院内石凳上；
2. 事件生成：`engine.tick()` 发现天气由"多云"变为"小雨"，命中 `weather_change` 模板且随机数通过 → 实例化事件；
3. 相关性过滤：角色在院子里（空间相关）+ 被雨淋到（人设相关）→ 通过；冷却已过 → 进入决策器；
4. 决策器：非勿扰时段、用户近 3 分钟无操作、主动度=均衡 → 判定"该说"；
5. 注入 OpenClaw：携带上述 stimulus，要求以角色身份主动开口；
6. OpenClaw 输出："哎呀，怎么突然下起雨来啦……旅行者，要不要进来躲躲雨？"（情绪：惊讶 + 关切）；
7. 联动推送：惊讶表情 + 台词气泡 + TTS 语音播放（+ 可选推送雨景氛围图）。

## 8. 统一消息协议（可用性的地基）

前端与编排层之间所有交互走一个 JSON 协议（WebSocket 为主、HTTP 兜底）：

```jsonc
// 前端 → 后端
{ "type": "user_text", "content": "今天心情不好", "scene": "living_room" }
{ "type": "scene_interact", "object": "window", "action": "open" }

// 后端 → 前端
{ "type": "dialogue", "text": "……", "emotion": {"type":"comfort","p":0.3,"a":0.4,"d":0.2}, "tts_url": "/audio/xxx.wav" }
{ "type": "image", "url": "/assets/cg/rain.png", "caption": "窗外下雨了呢" }
{ "type": "scene_state", "diff": {"weather":"rain", "hour": 23} }                 // 无图形场景可选：仅驱动氛围/配图
{ "type": "emotion", "emotion": {"type":"surprise","p":0.9,"a":0.9,"d":0.4} }   // 纯表情通道
{ "type": "speaking", "state": "start|end" }                                  // 口型开关
```

## 9. 可用性保障（贯穿全案）

1. **模块解耦可插拔**：每个能力都是独立进程/服务，任一模块可替换（换 LLM、换 TTS、换 Live2D 渲染库）不影响其他部分。
2. **逐级降级链**：主 LLM → 备用模型 → 规则回复；TTS → 系统语音 → 纯文本；Live2D → 静态立绘 → 头像气泡。角色**永远不哑**。
3. **低延迟体验**：LLM 流式输出 + 情绪标签先行 + TTS 边合成边播；生图等慢操作异步化，先给文字反馈。
4. **热更新**：角色卡、表情映射表、事件模板、图片库全部外部配置文件，改完热加载，无需重启。
5. **多端一致**：Web/PWA 为主，桌面用 Electron/Tauri 打包（共享同一后端）。
6. **监控与回滚**：对话质量抽样、情绪分布统计、模块健康检查；配置版本化，出问题一键回滚。

## 10. 实施路线图

| 阶段 | 内容 | 产出 |
|---|---|---|
| **P1 最小闭环（2~3 周）** | 本地 LLM（Ollama+角色卡）＋ Live2D（oh-my-live2d）＋ GPT-SoVITS；打通"文字对话→表情→开口说话" | 可对话的 Live2D 角色 Demo |
| **P2 心理系统（2 周）** | 情绪引擎（PAD+状态机）、好感度、记忆（向量库）、统一协议完善 | 有连贯心理变化与记忆的角色 |
| **P3 能力扩展（2 周）** | 图片展示（图库+CLIP 检索+ComfyUI 生成）、STT 语音输入 | 图文语音多模态对话 |
| **P4 本地角色模型接入（1 周）** | 对接本地 OpenClaw（角色脑模式），或挂载 LLaMA-Factory 微调的角色 LoRA | 复用本地角色资产 |
| **P5 数字化场景模拟（1~2 周）** | Python 实现场景状态机（时间/天气/地点/关系）+ 事件模板库 + 随机事件引擎 + 主动发言闭环 | 事件→过滤→决策器→OpenClaw→主动发言全链路可用 |

**建议先 P1→P2 快速出 Demo 验证体验；P5 数字化场景模拟可与 P4 并行（约 1~2 周即可打通"事件→主动发言"闭环）；每个阶段都可独立验收、独立上线。**
