# 本地生成与亲密度路由

> 目的：**亲密度到阈值后，画面改由本地 ComfyUI 生成**——不经过云端，所以不会被云端内容审核
> 挡掉或改写。云端出图快（约 15~20 秒）但受审核约束；本地出图慢（约 85 秒）但无审核、也不按张计费。

## 一、为什么需要两条路

| | 云端（阿里通义万相） | 本地（ComfyUI） |
|---|---|---|
| 速度 | 15~20 秒 | 85 秒（SDXL 1024×1024 / 28 步，实测 M5） |
| 成本 | 0.14 元/张 | 0 |
| 内容审核 | **有服务端审核**，敏感画面会被拒或改写 | 无 |
| 依赖 | 联网 + 额度 | 本地底模 + ComfyUI 进程 |
| 提示词体系 | 中文自然语言（`image_anchors.json`） | **danbooru 英文标签**（`image_anchors_local.json`） |

## 二、亲密度路由

`scene/delivery.py` 的 `_pick_image_backend(payload, cfg)`：读 payload 里的 `state.tier`
（由 `build_stimulus` 带出，源头是 `state.affinity`），到阈值就切本地。

档位定义（`scene/state.py`）：`stranger 0-30` / `familiar 30-70` / `close 70-101`。

```json5
// config.sessions.json → delivery.channels[0].config
"image_local": {
  "enabled": true,
  "min_tier": "close",          // 到「亲密」档才切本地
  "fallback_to_cloud": false,   // 本地失败**不回退云端**（见下）
  "steps": 24,
  "size": "832x1216",
  "host": "127.0.0.1:8188"
}
```

行为：`stranger`/`familiar` → 云端；`close` → 本地。投递结果里会写明用了哪个后端和原因
（如 `生图后端 local（亲密度=close≥close）`），日志可查。

**为什么不回退云端**：走到本地这条路，很可能正是因为画面会被云端拒。
失败后回退等于把这段提示词送给云端审核，多半还是失败，却暴露了内容。所以默认不回退，
要回退得显式把 `fallback_to_cloud` 打开。

`enabled: false` 时行为与加这个功能之前**完全一致**，不影响已有链路。

## 三、本地这套怎么搭起来的

环境原本是**半成品**：ComfyUI 装了（Mac 独立版 `~/ComfyUI-Installs/ComfyUI`，v0.28.0 + MPS），
但 `models/` 是空的、`torch` 等依赖也没装完。补齐的步骤：

1. **装依赖**：`standalone-env/bin/pip` 的 shebang 指向构建机路径（搬迁后失效），
   用 `python -m pip` 绕过；先装的 `torch` 不够，最后 `pip install -r ComfyUI/requirements.txt` 一次装齐
   （缺 `torchsde` 之类会一个个报错，不如一次装全）
2. **接共享模型目录**：写 `ComfyUI/extra_model_paths.yaml` 指向 `~/ComfyUI-Shared/`，
   模型与程序本体分离，重装 ComfyUI 不丢模型
3. **下载底模**：`animagine-xl-3.1.safetensors`（6.46GB，SDXL 动漫底模，danbooru 标签体系），
   走 ModelScope + `~/Documents/DSH/LocalAI/pget3.sh` 并行分段下载（约 4 分钟）
4. **拉起服务**：`./standalone-env/bin/python ComfyUI/main.py --listen 127.0.0.1 --port 8188`

> `pget3.sh` 结尾会报 `❌ GGUF 魔数校验失败`——**误报**，它的校验是给 GGUF 写的，
> 而这是 safetensors。用文件头自检确认：读前 8 字节得到头部长度，再解析 JSON 张量表。

## 四、两个后端的提示词差异（重要）

本地 SDXL 基本不认识中文，写「胡桃在璃月港」只会得到随机图。所以
`tools/gen_image_local.py` 会把命中的角色/场景换成 danbooru 标签并**剥掉中文**：

```
输入：胡桃在璃月港
→ masterpiece, best quality, very aesthetic, absurdres,
  hu tao (genshin impact), 1girl, solo, brown hair, long hair, twin tails,
  red eyes, flower-shaped pupils, black hat, ..., liyue harbor (genshin impact),
  chinese architecture, lantern, night, harbor, boat, scenery
```

词典在 `tools/image_anchors_local.json`（19 角色 / 3 场景 / 2 元素）。
后续如果要用 LoRA 提升角色一致性，底座就是这个 animagine（SDXL），
之前查到的胡桃 LoRA 也是 SDXL 系，可以直接接上。

## 五、用法

```bash
# 独立测试（不经过引擎）
python3 tools/gen_image_local.py "胡桃在璃月港" --out /tmp/a.png
python3 tools/gen_image_local.py --check          # ComfyUI 是否在跑、有哪些底模

# 全链路体检（含两个后端与路由）
python3 tools/verify_all.py
python3 tools/verify_all.py --online              # 附带真实调用
```

**实测**：本地生成 `胡桃在璃月港` → 85 秒 / 1400KB / 1024×1024；
用胡桃自己的视觉能力判图，确认「双马尾、黑帽、梅花瞳、中式服饰」特征吻合、
背景有璃月港的中式建筑与红灯笼、无明显结构崩坏。

## 六、对话模型也按亲密度切（两条路）

生图有路由还不够——**写提示词的那段文字**是对话 LLM 产出的。对话跑在云端，就等于
"图不出本机、但描述文字经过了云端"。所以对话模型也按亲密度分流：

| 亲密度 | 生图 | 对话模型 |
|---|---|---|
| stranger / familiar | 云端万相 | 云端（`deepseek-v4-flash` / `kimi-k2.6`） |
| close 但 < 95 | **本地 ComfyUI** | 云端 |
| close 且 ≥ 95 | **本地 ComfyUI** | **本地 `ollama/local`** |

### 两个门槛为什么不同

档位只有三档，而 `close` 是**最高档**。如果对话也只看档位，那你一进 close（≥70）就全切本地，
直接聊天会突然变慢变笨。所以对话额外加了**数值阈值** `min_affinity: 95`——
"很亲密"和"亲密"在档位上分不出来，得用数值。

`_tier_reached()` 同时支持 `min_tier` 与 `min_affinity`，两个都给了就都要满足。

### 两条路分别怎么切

1. **她主动发消息**：引擎调 `openclaw agent` 时可以 `--model` 直接指定，
   `_pick_chat_model()` 按亲密度选，实时生效
2. **你直接跟她聊**：这条走 OpenClaw 自己的 agent 配置，**引擎插不上手，只能改配置**。
   `main.py` 每 20 轮（约 10 分钟）调一次 `scene/openclaw_sync.py` 做同步

`openclaw_sync.py` **只做键级合并**：读现有数组 → 按 id 找目标项 → 只改 `model.primary` → 原子写回。
它绝不整体重写 `agents.list`——那正是 LocalAI 的补丁会踩的坑（见 `OPENCLAW-OWNERSHIP.md`）。
另外它比较的是**生效值**（agent 没设时继承 `agents.defaults.model.primary`），
否则每次巡检都会白写一次、还把继承关系钉成显式覆盖。

## 七、LoRA：让脸真的是胡桃

提示词锚定只能到"像胡桃的路人"：双马尾✅ 黑帽✅ **梅花瞳❌ 衣服纹样❌**。
LoRA 是唯一真正解决这个的路子（原理见对话记录；要点：给底模打小补丁，
绑定底座架构，**云端万相用不了**，只对本地这条路有意义）。

**实测结论（同提示词、同随机种子 `--seed 12345`，只差有没有 LoRA）**：

| 维度 | 无 LoRA | 有 LoRA |
|---|---|---|
| 梅花瞳 | ❌ 普通圆形高光 | ✅ 明确梅花瞳 |
| 乾坤泰卦帽 | 像普通礼帽，燕尾飘带弱化 | 帽型挺括、梅花枝、蓝流苏、对称双燕尾完整 |
| 衣服纹样 | 几乎无 | ✅ 彼岸花/卷草暗纹清晰 |
| 气质 | 温和偏 generic | 挑眼型、尖脸、坏笑，贴合角色 |

无崩坏、无跑偏。**用的是 `TassosTV/hutao_lora`（27.6MB，SDXL 架构，rank=4）**——
一开始担心 rank 太低影响弱，实测证明担心多余，而且这是在**非训练底座**（animagine）上就有的效果。

### 底座选择：Illustrious 胜出

用同一提示词、同一 `--seed 12345` 做过三方对照（animagine 无 LoRA / animagine+LoRA / Illustrious+LoRA）：

| | animagine + LoRA | Illustrious + LoRA |
|---|---|---|
| 胡桃还原度 | 被直接认出 "Hu Tao" | 梅花瞳、帽饰、衣装细节全对 —— **持平** |
| 画质光影 | 稍平 | **水面反光、灯笼暖光、夜空层次更细腻** |
| 结论 | | ✅ 选它 |

代码里的底座优先级本来就是 `--ckpt` > 含 `illustrious` > 含 `animagine` > 第一个，
**两个底座都在时会自动选 Illustrious**，不需要改配置。

> 获取过程的教训：`Illustrious-XL-v2.0` 这个文件用 `pget3.sh` **连续两次下坏**
> （多出 579MB / 933MB），改用 `~/Documents/DSH/_shared/pget_verified.py` 才成功。
> 差别在于后者**逐段强校验**（HTTP 必须 206 + 字节数严格相等）、失败**从零重下不追加**、
> 顽固段还会**对半拆分**再试。详见该文件头部注释。

### ⚠️ 本地模型没有视觉能力

`ollama/local`、`ollama/xiaoman` 以及所有 deepseek 模型的 `input` 只有 `["text"]`，
**只有 `moonshot/kimi-k2.6` 是 `["text","image"]`**。

后果：**亲密度路由把对话切到本地后，胡桃就失去看图能力**（`image` 工具会失败）。
需要她读图时（判图、看用户发的照片、检查自己生成的图），要么把对话模型切回云端，
要么单独用一个有视觉的 agent 来做这件事。

### 命令

```bash
python3 tools/gen_image_local.py --list-lora          # 看有哪些 LoRA
python3 tools/gen_image_local.py "胡桃在璃月港" --out /tmp/a.png          # 默认带 LoRA
python3 tools/gen_image_local.py "..." --no-lora --out /tmp/b.png        # 单次关掉
python3 tools/gen_image_local.py "..." --lora genshin_full --lora-strength 0.6
```

默认 LoRA 在 `image_anchors_local.json` 的 `default_lora`（模糊匹配文件名）。
底模选择优先级：`--ckpt` > 名字含 `illustrious` > 含 `animagine` > 第一个。

## 八、整合时踩到的三个接缝问题

单项功能都能跑，不代表能配合。这三个都是**交界处**的问题，单测发现不了：

### 1. 本地模型稳定丢掉 `[[img_gen]]` 标记（最要命）

**症状**：亲密度到阈值切本地后，胡桃**永远发不出图片请求**——"本地生图"整条路根本触发不到。

**排查过程**：直接让它"原样输出这一行"能写对；但用引擎的真实指令（人设 + 输出形式约束）
就漏。加粗提醒、末尾强调"必须包含这一段，否则图画不出来"**都没用**——9B 在扮演角色时顾此失彼。

**修法**：不能靠提示词，只能引擎兜底。`_fallback_image()`：模型没写标记、而**引擎自己要求过配图**
（事件带 `image` 字段，或指令文本里写了 `[[img_gen: ...]]`）时，由引擎补上。
只在模型漏了才补，也不会替她擅自加图。

> 写这个兜底时又踩一次：读的是 `payload["event"]["instruction"]`，但 `instruction` 在
> **payload 顶层**（`build_stimulus` 的返回结构）——于是兜底静默失效，跑完连"媒体:"都不出现，
> 很难看出问题。现已改为读顶层。

### 2. `image` 工具只允许读工作区内的图

**症状**：传 `/tmp/xxx.png` 一律返回「路径不在允许访问的目录里」。
一度被误判成"本地模型没有视觉能力"（这两件事症状很像）。

**修法**：`tools/ask_vision.py` 先把图**暂存进 `~/.openclaw/workspace/images/_vision/`** 再读。

### 3. 视觉能力与对话模型路由解耦

只有 `moonshot/kimi-k2.6` 声明了 `input: ["text","image"]`；`ollama/local`、`ollama/xiaoman`
和所有 deepseek 都是 `["text"]`。所以本地模式下她看不了图。

**修法**：不要用同一个开关管两件事。`tools/ask_vision.py` **显式指定有视觉的模型**，
与对话模型路由无关——不管对话跑在哪，看图都可用。
并且**读不到就报失败，绝不输出"按经验推测"**（实测这个模型会编）。

## 九、注意

- ComfyUI 是**常驻进程**，关了之后本地生图会失败（投递会记 `img_gen 未产出文件`）
- 本地出图 85 秒会让投递整体变慢，`image_local_timeout` 默认给了 900 秒
- 首次出图要加载 6.5GB 底模进内存，第一张会明显更慢
