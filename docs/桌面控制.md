# 桌面控制（macOS）研究与落地

> 目标：让 OpenClaw 的角色 agent（胡桃）能"看见并操作"这台 Mac 的桌面。
> 状态：**已打通并端到端实测通过**（2026-09-13）

---

## 一、OpenClaw 官方支持的 3 条桌面控制路径

| 路径 | 机制 | 前置条件 | 适用 |
|---|---|---|---|
| **① PeekabooBridge** | OpenClaw.app 作为**权限代理宿主**，`peekaboo` CLI 作为客户端（UNIX socket） | 安装 OpenClaw.app → 设置开启 Peekaboo Bridge → 装 `peekaboo` CLI → 授权辅助功能/屏幕录制 | 最完整的 macOS GUI 自动化（截图/点击/菜单/对话框/Dock/窗口） |
| **② Codex Computer Use** | 内置 `codex` 插件安装 Codex 的 `computer-use` MCP 插件 | 启用 codex 插件 | Codex 模式下的原生桌面控制 |
| **③ cua-driver MCP**（TryCua） | 注册 `cua-driver mcp` 为普通 MCP server | 配 `mcp.servers` | CUA 驱动的 pid/窗口/元素索引工作流 |

**本项目采用的路径**：**`exec` + 自建工具箱 + Skill**（零第三方依赖、可自检、权限面可控），
上表三条作为将来需要更强能力（如元素级定位）时的升级路径。

---

## 二、已落地的实现

| 组件 | 位置 | 作用 |
|---|---|---|
| **工具箱** | `tools/desktop.py` | 封装截屏 / 应用枚举 / 激活 / 打开 / 窗口 / 点击 / 输入 / 按键 / 菜单 + **能力自检** |
| **技能** | `~/.openclaw/workspace/skills/desktop-control/SKILL.md` | 告诉 agent 何时用、怎么用、缺权限时如何向用户报告、危险操作先确认 |

### 命令一览

```bash
python3 tools/desktop.py info                       # 能力自检（推荐先跑）
python3 tools/desktop.py screenshot [--path P]      # 截屏
python3 tools/desktop.py apps                       # 可见应用列表
python3 tools/desktop.py activate "WeChat"          # 切到前台
python3 tools/desktop.py open <路径|URL>
python3 tools/desktop.py windows "WeChat"           # 窗口列表
python3 tools/desktop.py click <x> <y>              # 坐标点击
python3 tools/desktop.py type "文本"                 # 输入
python3 tools/desktop.py key 36 [--cmd]             # 按键（36=回车）
python3 tools/desktop.py menubar "App" "菜单" "项"
```

## 三、权限矩阵（实测结果）

| 能力 | 需要权限 | 当前状态 |
|---|---|---|
| 截屏 / 看屏幕 | 屏幕录制 | ✅ 已授权（实测 3840×2486 全分辨率） |
| 枚举可见应用 | 自动化（AppleScript） | ✅ 可用 |
| 打开 / 激活应用 | 自动化 | ✅ 可用 |
| **点击 / 输入 / 按键 / 窗口 / 菜单** | **辅助功能** | ✅ **已授权**（自检通过，`-1728` 错误消失） |
| 精确坐标点击（可选增强） | 安装 `cliclick`（可只给该二进制授权，比给 `node` 授权窄得多） | ⏳ 可选 |

> 官方文档警告：**不要给通用 `node` 二进制授予辅助功能**——那会让任何 npm 包继承 GUI 自动化权限。
> 本项目当前由网关进程（node）持有权限，属"方便但权限面较宽"的权衡；若要收窄，
> 可改装 `cliclick` + 只授权该二进制，或改走路径①（签名 App 持有权限）。

## 五、视觉读屏（已打通 ✅）

截图本身只是文件；**理解屏幕内容**需要再用 `image` 工具（视觉模型）分析：

```bash
# 1) 截屏
python3 tools/desktop.py screenshot        # → /tmp/dsh_shot.png
# 2) 交给 agent 的 image 工具分析（prompt 按需具体化）
```

- 依赖：主模型需支持图像输入（当前 `moonshot/kimi-k2.6` 的 `input: ["text","image"]` ✅）
- 技能 `desktop-control` 中已写入该工作流（含"读完用自己口吻转述"的要求）

**端到端实测**（2026-09-13）：用户让胡桃"看看屏幕"，她截屏 → 读图 → 汇报出
终端里在跑的项目、浏览器标签页（DeepSeek 开放平台）、菜单栏时间与电量、Dock 图标列表，
并用人设口吻总结用户在做什么 ✅

## 六、坐标换算（重要）

截图是 **Retina 全分辨率**（如 3840×2486），而 `click` 使用**逻辑点**（通常为分辨率的一半，1920×1243）。

```
逻辑点 = 像素 ÷ Retina 缩放比（通常 2）
```

技能文档中已写明该换算规则，避免 agent 点错位置。

## 七、安全须知

1. **胡桃可从微信触达**：她现已具备桌面控制能力，等于"微信侧可影响本机 GUI"。用户已评估并接受该风险；
2. **危险操作须先确认**：技能中已明确要求——删除文件、发送消息、支付、关机等必须先向用户确认；
3. **异常访问监测**：`scene/security.py` 会在微信渠道出现未知发送者时告警（见 `docs/安全加固.md`）；
4. **可选的进一步收敛**：
   - 只给 `cliclick` 授权（而非 node）
   - 对危险命令启用 exec 审批：`exec-approvals` 配 `ask`
   - 或改走 PeekabooBridge（签名 App 持有权限）

## 八、后续可选升级

| 方向 | 收益 | 代价 |
|---|---|---|
| 装 `cliclick` | 坐标点击更稳、支持拖拽/双击/连点 | 一个 brew 包 |
| 装 OpenClaw.app + `peekaboo` | 元素级定位（按控件名点击，不依赖坐标）、菜单/对话框/Dock/窗口管理更完整 | 安装 App + 另配权限宿主 |
| 接视觉模型 | 让 agent 直接"看懂"截图内容（而非只存文件） | 走 `image` 工具或视觉模型 |
| `cua-driver` MCP | 完整的计算机使用（CUA）能力 | 引入第三方 MCP |
