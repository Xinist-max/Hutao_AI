# Live2D 集成方案（OpenClaw 胡桃 × Live2D 表情同步）

> 目标：把 OpenClaw（胡桃角色脑）接入 Live2D 模型，在 macOS 上运行，
> **表情与对话内容同步，且尽可能丰富**（表情文件 + 原始参数 + 动作 + 口型）。

---

## 1. 结论先行（选型）

| 方案 | 落地难度 | 表情丰富度 | 口型同步 | 推荐度 |
|---|---|---|---|---|
| **A. VTube Studio + Public API**（推荐） | ★ 低（装个免费 App，开 API 即可） | ★★★ 表情/动作/**任意参数注入**全支持 | ★★★ 内置 LipSync + 可注入 | **首选** |
| B. Web 渲染（pixi-live2d-display + 本地服务） | ★★ 中（需自建渲染页与驱动逻辑） | ★★★ 完全可控，但要自己实现 | ★★ 需自己做音频分析 | 备选 |
| C. 原生 App（Electron/Tauri 包装 B） | ★★★ 高 | ★★★ | ★★ | 后续可选 |

**推荐 A**：VTube Studio（macOS 原生，Steam 免费）提供 WebSocket Public API，
可直接触发**表情文件**、**动作热键**、并**逐帧注入任意模型参数**（眉毛/眼睛/嘴巴/头部/身体/呼吸），
是"表情越丰富越好"最短路径。你只需后续提供 Live2D 模型。

> 你的机器条件（已探明）：macOS 26.6.2 / Apple Silicon；**Node v24 自带 WebSocket（桥接可零依赖）**；
> 系统中文 TTS 可用（`say`，用于口型同步）；VTube Studio 待安装。

## 2. 总体架构

```
┌────────────── 现有工程（Python） ──────────────┐
│ 璃月港场景引擎 → 事件 → OpenClaw(胡桃回复)      │
│   ①捕获回复文本  ②解析情绪标签  ③TTS 合成音频   │
└───────────────┬───────────────────────────────┘
                │ HTTP/JSON（本地回环，127.0.0.1）
                ▼
┌────────────── live2d_bridge（Python 或 Node） ────────┐
│  情绪 → 表情映射 · 参数曲线(缓动/混合) · 口型包络       │
│   blink/凝视/呼吸/待机 自动行为 · VTS API 客户端        │
└───────────────┬───────────────────────────────────────┘
                │ WebSocket ws://127.0.0.1:8001（VTS Public API）
                ▼
┌────────────── VTube Studio（macOS） ──────────────────┐
│  加载胡桃 Live2D 模型 → 表情/动作/参数实时渲染          │
└────────────────────────────────────────────────────────┘
```

**职责划分**：引擎负责"说什么/什么情绪"；bridge 负责"怎么演"；VTS 负责"画出来"。
三者通过本地回环通信，互不侵入——符合本项目"模块可插拔"的一贯设计。

## 3. 情绪同步设计（核心：越丰富越好）

### 3.1 情绪从哪来（三级来源，成本从低到高）

| 级别 | 来源 | 说明 |
|---|---|---|
| ① 主 | **OpenClaw 回复内嵌情绪标签** | 在注入事件时要求胡桃在回复首行输出 `[[emotion:joy,intensity:0.8]]`，引擎解析后**剥掉标签**再展示/朗读（对用户不可见） |
| ② 兜底 | **本地关键词分类器** | 标签缺失时按关键词/标点判定（如"哈哈/嘿嘿"→joy，"哼"→annoyed，"……"→sad），零 API 成本 |
| ③ 增强（可选） | 小模型分类 | 本地小模型对文本做情绪分类，精度更高（额外成本，默认关闭） |

### 3.2 双层情绪模型（瞬时 + 持续）

```
瞬时情绪(E_t)：本条消息的情绪，强度 0~1，用于"立刻的表情反应"
持续心情(M_t)：滑动累积 + 时间衰减，用于"底色表情"（如：连续开心 → 嘴角常带上扬）
最终参数 = 0.65 × 瞬时映射 + 0.35 × 持续心情   （可配置权重）
```

- 衰减：`M ← M·λ + E·(1-λ)`（λ≈0.85，每分钟一次）；情绪不会"说完立刻面无表情"。
- 戏剧反差联动：魈/钟离相关事件（认知反差）可额外注入 `smug`（得意/狡黠）底色。

### 3.3 情绪分类（首批 14 类，可扩展）

`joy 开心` `amused 逗趣` `smug 得意` `shy 害羞` `surprise 惊讶` `annoyed 恼火`
`sad 难过` `worried 担心` `curious 好奇` `thinking 思索` `sleepy 困倦`
`serious 郑重` `excited 兴奋` `neutral 平静`

### 3.4 表情驱动三层（丰富度来源）

| 层 | 机制 | 说明 |
|---|---|---|
| **L1 表情文件** | VTS `ExpressionActivationRequest`（.exp3.json） | 模型自带的成品表情，优先使用 |
| **L2 参数注入** | VTS `InjectParameterDataRequest`（逐帧写参数） | **最丰富**：即使模型只有少量表情文件，也能连续混合出无限表情 |
| **L3 动作** | VTS `HotkeyTriggerRequest`（.motion3.json 热键） | 待机/说话/点头/挥手等身体动作 |

**L2 参数映射表（示例，按 Cubism 标准参数 ID）**

| 参数 | 开心 | 恼火 | 难过 | 惊讶 | 害羞 | 思索 | 得意 |
|---|---|---|---|---|---|---|---|
| `ParamBrowLY/RY` 眉高 | +0.5 | −0.6 | −0.2 | +0.8 | +0.2 | +0.1 | +0.3(单侧) |
| `ParamBrowLAngle/RAngle` 眉角 | +0.2 | +0.5 | −0.4(内压) | +0.3 | −0.1 | 0 | +0.4(单侧) |
| `ParamEyeLOpen/ROpen` 眼开度 | 0.7 | 0.5 | 0.4 | 1.2 | 0.6 | 0.8 | 0.6 |
| `ParamEyeBallX/Y` 眼球 | 0 | 0 | −0.3 | 0 | −0.5 | (−0.4,+0.5) | +0.3 |
| `ParamMouthForm` 嘴形 | +1.0 | −0.8 | −0.6 | 0 | +0.4 | −0.2 | +0.7(歪) |
| `ParamMouthOpenY` 张嘴 | 0.3 | 0.2 | 0.1 | 0.9 | 0.15 | 0.1 | 0.25 |
| `ParamAngleX/Y/Z` 头部 | 0/+5/8 | 0/−3/−5 | −5/−8/0 | +3/+8/0 | −6/+4/10 | +4/+6/−8 | 0/+2/12 |
| `ParamBodyAngleZ` 身体倾 | 4 | −2 | −3 | 2 | 6 | 0 | 5 |
| `ParamBreath` 呼吸 | 0.6 | 0.8 | 0.4 | 0.9 | 0.7 | 0.5 | 0.6 |

> 若模型有 `ParamCheek`（脸红）、`ParamTear`（泪）、`ParamHairFront`（发丝）等，则额外驱动，进一步丰富。

### 3.5 自动行为（不依赖消息也会动）

- **眨眼**：每 2~6 秒随机一次，双层（快闭+缓开）
- **凝视**：眼球跟随鼠标/摄像头（VTS 内置，或注入 `ParamEyeBallX/Y`）
- **呼吸**：`ParamBreath` 正弦（周期 3.5s）
- **待机摇摆**：`ParamBodyAngleZ`/`ParamAngleZ` 低频正弦 + 随机微动作
- **说话时的额外表现**：眉毛跟随重音起伏、句末点头

## 4. 口型同步（TTS → 嘴型）

两种实现（可叠加）：

1. **音频包络注入（自研，精准）**：TTS 音频播放的同时，实时计算 RMS 包络 →
   平滑后写入 `ParamMouthOpenY`（并让 `ParamMouthForm` 随情绪变化，如开心时嘴角上扬）。
   - 优点：与播放完全同步、可离线、可精细控制
2. **VTS 内置 LipSync**：VTS 从麦克风拾音驱动（需开麦，环境噪声敏感）——作为兜底

**TTS 选型（Mac 上渐进）**
| 阶段 | 方案 | 说明 |
|---|---|---|
| 起步 | macOS `say -v Tingting/Meijia` | 零安装、系统内置，先跑通链路 |
| 进阶 | GPT-SoVITS / CosyVoice（本地） | 胡桃音色克隆，质量接近真人（需 GPU 或 Apple Silicon 加速） |
| 可选 | 直接播放已有语音素材 | 用于特定剧情节点的预录台词 |

## 5. 模型准备清单（你后续提供）

**必需文件**（Live2D Cubism 3/4 导出）
```
胡桃/
├── 胡桃.model3.json        # 模型定义（含表情/动作/物理引用）
├── 胡桃.moc3               # 模型本体
├── 胡桃.physics3.json      # 物理（头发/衣摆摆动）
├── 胡桃.cdi3.json          # 参数/部件说明（**重要：便于自动映射参数**）
├── textures/               # 贴图
├── motions/                # 动作 .motion3.json（待机/说话等，越多越好）
└── expressions/            # 表情 .exp3.json（越多越好）
```

**要求与建议**
1. **参数 ID 尽量采用 Cubism 标准命名**（`ParamAngleX/Y/Z`、`ParamEyeLOpen`、`ParamMouthOpenY`、`ParamMouthForm`、`ParamBrowLY/RY`、`ParamBodyAngleZ`、`ParamBreath`…）——
   本方案的第 L2 层（参数注入）依赖这些 ID；非标准命名也能做，只需在映射里改配置。
2. 有 `.cdi3.json` 最好——bridge 会自动读取参数清单，缺失的参数自动跳过（不会报错）。
3. 表情文件建议覆盖：开心/生气/难过/惊讶/害羞/得意/困倦（至少 6~8 个）。
4. 动作建议：待机(idle)、说话(talk)、点头、摇头、挥手、惊讶后仰 等。
5. 使用授权：自绘模型最稳妥；第三方模型请注意作者授权（仅个人使用）。

## 6. 与现有工程的集成点（保持可拓展性）

新增文件（不侵入现有模块）：

```
live2d/
├── bridge.py            # 情绪→表情 桥接服务（HTTP 接收 + VTS WebSocket 下发）
├── emotions.py          # 情绪分类与双层情绪模型（瞬时 + 持续）
├── mapping.json         # 情绪→表情/参数/动作 映射（**可配置，换模型只改这里**）
└── README.md            # 使用说明
```

引擎侧只加一个**投递通道**（沿用既有插拔式设计）：

```jsonc
// config.live2d.json 里
"delivery": { "channels": [
  { "name": "live2d", "config": { "url": "http://127.0.0.1:8630/say" } },  // 新增通道
  { "name": "openclaw_sessions", "config": { ... } },                     // 同时/或仅微信
  { "name": "console" }
]}
```

这样：**要 Live2D 就加通道，不要就去掉**——微信投递、Live2D 展示可并存（同一条回复既发微信也上屏），互不干扰。

## 7. Mac 落地步骤（预计 1~2 小时可跑通）

1. **装 VTube Studio**（Steam 免费）→ 启动，导入你的胡桃模型
2. **开启 API**：VTS 设置 → API → 打开 *Allow Plugin API*（默认 `ws://127.0.0.1:8001`）
3. **授权插件**：首次连接时 VTS 会弹出授权框，点允许（bridge 保存 token 后不再弹）
4. **装桥接依赖**：`pip install websockets`（或使用 Node 24 原生 WebSocket 版本，零依赖）
5. **启动桥接**：`python3 live2d/bridge.py`（或开机自启）
6. **联通测试**：`curl -X POST localhost:8630/say -d '{"text":"你好呀旅行者","emotion":"joy"}'`
   → 应看到胡桃表情变化 + 嘴型开合
7. **接上引擎**：用 `config.live2d.json` 启动场景引擎 → 胡桃的见闻分享会实时上屏

## 9. 验证方法

- **表情正确性**：构造 14 类情绪测试文本，逐条投递，人工确认表情与语义一致（可截图存档）
- **连续性**：连续 5 条同情绪消息 → 检查"底色"是否累积；插入 1 条反向情绪 → 检查是否平滑过渡（无跳变）
- **口型同步**：录屏检查嘴型开合与音频波形一致（可用 ffmpeg 抽帧对比）
- **稳定性**：连续运行 2 小时，检查桥接重连（VTS 重启后自动恢复）与内存占用
- **降级**：VTS 未启动时，bridge 应静默重试，**不影响微信投递主链路**

## 10. 风险与备选

| 风险 | 应对 |
|---|---|
| VTS 无 Linux/服务器版（仅桌面） | 本机 macOS 使用没问题；若将来要上云，改用方案 B（Web 渲染） |
| 模型表情文件少 | L2 参数注入可"无中生有"，靠参数混合出丰富表情 |
| 模型参数非标准命名 | `mapping.json` 可配置；`.cdi3.json` 自动读取 |
| Apple Silicon 上 GPT-SoVITS 性能 | 先跑通链路，音色升级后置；也可用云端 TTS 兜底 |
| 长时间运行显存/CPU 占用 | VTS 本身较轻；bridge 只做参数计算，CPU 占用极低 |
